# Android C3 候选试听安全设计（草案，默认 No-Go）

本设计基于 #85（`d1c95265a1cfb3e312c2f3e1e356230016d74f53`），是未来实施和评审的候选方案，不是生产实现、安全证明或发布许可。当前不接线、不播放、不进行网络验证；候选试听独立开关默认关闭，未完成下述实现、设备验证及独立安全评审前不得打开。关闭或策略不可用时不创建候选播放请求，也不回退到普通播放器。正常电台播放不应被本方案意外改变。

## 威胁与现状

候选 URL、重定向 Location、播放列表及其相对引用均不可信。看似公网的地址可能经重定向、DNS 重绑定、HLS 子清单、分片、初始化段或加密 key 请求访问回环、私网、链路本地、设备/云元数据服务等；校验入口 URL 或预解析一次并不足以保护后续实际连接。`PlayerHolder` 目前以普通 `OkHttpClient` 构造 `OkHttpDataSource.Factory`；`CheckStream` 的 `GuardDns` 仅用于探活客户端，不保护 Media3 播放器。探活成功不是播放授权，也不是连接安全证明。

## 候选限定的受控网络边界

- 为候选会话单独构造受控 Media3 DataSource/媒体源工厂与专用网络客户端；确保 progressive、HLS 主/子清单、分片、初始化段、key 及未来协议产生的每一请求都经过同一策略，无法确认覆盖的协议或加载路径一律拒绝。禁止使用默认工厂、备用数据源或任何未经验证的回退。单源 Station 只是模型，不构成安全隔离。
- 每次请求以及每次重定向先规范解析并验证目标，只允许经评审的 HTTP(S) URL；拒绝 userinfo、畸形主机、非允许协议及所有非公网 literal，包括 IPv4/IPv6、IPv4-mapped IPv6 和各种等价/非规范编码，明确端口和重定向次数上限。相对 Location 和清单引用须相对实际响应 URL 解析后再校验；禁用客户端自动重定向，手动逐跳重建并审核，错误/超限即失败关闭。不得因同源或先前校验跳过检查。
- 连接时使用专用 DNS 策略检查实际解析结果，所有返回地址必须符合明确、经评审的公网地址策略（包括保留/特殊用途段）；混合公私结果拒绝整次解析。实际 socket 只能连接该次已验证的地址，重试、重解析、网络切换和每次新连接均重新执行；不能先检查后让另一个解析器独立解析。literal 可能绕过 DNS，因此须单独在 URL 和连接边界检查。TLS 仍按原始主机名执行证书及 hostname 校验，不关闭验证。
- 禁止系统/显式代理及代理自动发现，避免代理代解析或代连接绕过本地验证；代理环境不能满足策略则失败关闭。专用连接池不得与普通播放共享；默认禁用跨主机连接合并及未经重新授权的连接复用，必要时禁用复用或严格绑定已校验主机、地址、网络与策略版本，不能仅依赖 DNS 回调拦截复用连接。禁止 QUIC、替代服务及其他绕过已验证连接路径的传输，除非另有等价证明。策略变更或网络切换时关闭旧池和在途会话。
- 明确请求超时、大小及重定向预算、取消和错误反馈；不把 URL、token、key 或用户信息写入日志。用户主动点击才连接，提示电台/CDN 可见 IP 与流量消耗；不自动探活、预取或在停止后恢复旧台。遇到不支持、拒绝或无法证明安全时显示不可试听，不降级直连。

以上是待实现的要求而非现有 OkHttp/Media3 默认行为保证；API 和库版本具体可行性须通过实现审计与真设备证据确认，做不到则继续关闭。

## 会话副作用及显式加入边界

当前 `AppVm.startPlay` 请求通知权限、异步 `lib.recordRecent`、可能 `logos.prime` 后调用 `PlayerHolder.play`；状态流还消费质量、元数据与开启时的收听统计，播放时可累计流量估算。`PlayerHolder` 具有音量及多源成功记忆等行为。因此直接复用正常播放不能声称只读，绕过 `startPlay` 也不能证明其他出口安全。

未来须以不可混淆的会话身份贯穿播放器及所有监听器，在暂停、恢复、重试、切台、服务重建、异步迟到事件及音量操作中证明隔离：候选不得写最近、收听统计、质量、收藏、源成功记忆、歌曲历史、台标或每台/全局持久音量，不启动 Timeshift 或额外曲讯/台标请求；试听期间必要的临时音量不得污染正常音量，结束后恢复原状态。通知、MediaSession、Widget 只呈现临时会话且不得触发 artwork 网络，正常播放的最近、统计和音量语义不受影响。若任何出口无法证明隔离，禁止试听。

试听绝不自动加入个人电台或收藏。仅由用户显式确认加入 MyRadio，执行 #85 的全库全部源和个人层 URL 身份查重、休眠收藏回绑、清洗、受控探活、网络策略、最终 UTF-8 字节/行数上限、串行幂等和原子提交；现有 MyRadio 尚不满足所有条件，不能直接视为安全实现。加入成功以实际提交和重载为准，失败清楚反馈；sidecar 更新删除不删除已加入数据。加入是另一个有意的持久化操作，不因为试听安全就自动获准。

## 设备测试与放行门

- 使用隔离可控 DNS、HTTP(S) 服务和请求日志在 Android 仪器测试中断言真实连接目标，而非只测 URL helper：公网到私网逐跳、重定向循环/超限/畸形、相对引用、IPv4/IPv6 literal 及映射/编码变体、混合 DNS 答案、重绑定、重试和网络切换均拒绝，禁止命中受保护目标。测试隔离注入只存在测试构建，不放宽生产策略。
- 测试真实 Media3 progressive 与 HLS 主/子清单、分片、初始化段和 key 的每条路径，包括各层重定向、相对 URI、key 指向内网，以及加载失败后无默认工厂回退；测试跨主机 HTTP/2 合并、连接池复用、代理/PAC 和 DNS 绕过，验证实际 peer 地址及请求计数。覆盖取消、超时和旧连接销毁；适配设备与依赖版本范围须明确。
- 对最近、统计、质量、音量、源记忆、收藏、个人文件及其他出口做播放前后快照与异步迟到负断言；测试暂停/恢复、失败/重试、会话替换、进程/服务生命周期，并对照正常播放保留既有行为。显式加入单独覆盖去重、失败、并发和持久化；默认关闭时断言无候选请求和无副作用。
- JVM mock 和单一成功播放不足以证明连接安全；须记录设备、Android/Media3/OkHttp 版本、测试方法和可复现结果，完成跨端、安全、隐私与发布评审及回滚演练。任何覆盖缺口、环境限制或未验证机制均为 No-Go；本草案不宣称这些证据已经存在。
