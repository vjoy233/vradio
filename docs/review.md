## 总评

**这是一个「约束自觉」极强的小型项目，在它选定的场景里做到了一流水准。** 三级播放策略、双上游同步、字节级探活、原子写盘这些设计都是对着「国内直连环境 + 流地址天然漂移」这个真实敌人的，不是摆设。零依赖不是偷懒，而是与「clone 即用」的产品承诺自洽的选型。

## 一、架构设计

### 做对了的事

1. **三级播放策略是本项目的核心资产**（index.html:134-187）。mp3 直流 → hls.js 直连 → 本地代理的顺序不是拍脑袋，是实测出来的（央广 ngcdn 必须走 ③）。蜻蜓 m3u8→mp3 的自动换算（index.html:137-138）把最高延迟路径变成了最低。这个策略的**顺序不能乱**已被 AGENTS.md 固化为团队知识，好。
2. **代理分片重写**（index.html:175-180）解决了 hls.js 走代理时相对分片被解析到 localhost 的坑，`proxyBase` 的设计正确且必要。
3. **同步引擎双入口**（update-sources.js:181-185）：`require.main` 守卫让同一份代码既是库又是 CLI，server.js 与 npm script 复用，没有重复逻辑。
4. **防御性工程成体系**：上游内容下限校验（MIN_CN_ENTRIES=500）、合并结果下限熔断（MIN_TOTAL=800）、写盘前备份、temp+rename 原子替换（update-sources.js:154-173）。这意味着上游仓库被投毒或网络半途而废时，本地数据不会坏。
5. **探活按「持续吐数据」验收**（update-sources.js:43-62）：对 xmcdn 假流（206 但只有 336B）的免疫是写进代码的实战经验，m3u8 还会取分片实测、master playlist 递归解一层，深度受限。这是很多同类项目都没有的严谨度。
6. **playToken 世代令牌**（index.html:92, 144-161）：快速连续点播时旧播放链路的回调全部失效，避免了「串台」这一类播放器最恶心的 bug。

### 风险与建议

1. **index.html 单文件接近可维护性上限**。当前 355 行还算紧凑，但 README roadmap 上的回听/睡眠定时/PWA/流派细分每一项都要往这一个文件里塞。建议在动 PWA 或回听这类大件**之前**，先做一次零构建拆分：`index.html`（结构）+ `app.js`（列表/搜索/收藏）+ `player.js`（播放引擎）+ `sync.js`（同步/体检），普通 `<script>` 标签顺序引入即可，**不需要引入构建步骤**，零依赖承诺不破。拆分的收益不是性能而是：播放引擎（最复杂、最难测的部分）获得独立的可测试边界。
2. **前端状态管理是隐式的**。`stations/favs/cat/keyword/playingKey/connectingKey/playToken/renderStamp` 全是模块级自由变量，靠 `render()` 全量 innerHTML 重建 + `renderStamp` 哨兵（index.html:239, 321）维持一致性。当前规模能 hold 住，但体检的「增量更新依赖 renderStamp 未变 + renderOrder.indexOf(s)」是 O(n²) 的隐性耦合（index.html:322），每加一个异步功能这类哨兵就多一个。拆分时顺手把「状态 → 单一 render 入口」的约定显式化即可，不必上框架。
3. **体检结果不持久化**。体检标记（s.health）只活在内存里，刷新即丢、换源排序也不参考它。建议服务端落一个 sidecar JSON（如 `health.json`：url → lastOk 时间戳），三个收益：刷新不丢、`variants()` 可以把已知死链排到最后（减少用户等待换源的时间）、多次体检可以做成增量（只测上次失败的）。
4. **同步 merge 语义不一致**：首屏加载 radio.txt 用 `merge=true`（STARTER 与 radio.txt 并存，index.html:339-340），同步完成后重新加载用 `merge=false`（index.html:296，「常听」分类消失），导入也是 `false`。用户视角的表现是「点完同步源，常听分类没了」。建议统一：要么 radio.txt 永远 replace + STARTER 单独作为一个持久分区，要么都 merge。
   > ✅ **代码复核补充**：同步后 **my-radio.txt 的个人台也会从列表消失**——同步处理器只重拉 radio.txt（index.html:295-296），启动时 merge 进 `stations` 的个人条目被 `setData(..., false)` 整体覆盖，刷新页面才恢复；「导入列表」同样会冲掉个人台与常听。这不只是「常听消失」，是个人数据在会话内静默丢失。
   > ✅ **二审代码复核：成立**。
   > 📌 已定方向（owner 已确认，见第九节决策 B）：主列表 replace + 个人层常驻——同步/导入后自动重拉 radio.txt 与 my-radio.txt 重新并入。
5. **STARTER 层与 radio.txt 大面积重复（实测统计，修正原文「低频」判断；二审再度修正计数；三审升级为 URL 级）**：**三审实测 STARTER 全部 18/18 个源 URL 原样存在于 radio.txt**（比二审的「14/14 台至少一源重复」更强——每个源、不是每台）；精确重名 **6 例**（一审计 4 例系漏计：CNR 中国之声 / CNR 音乐之声 / CRI 环球资讯广播 FM90.5 / CRI 怀旧金曲频道 + **上海东广新闻台[音乐] / 上海交通台 FM105.7[地方]**）——http 模式下「常听」分区整个是重复数据；两个 key（`c|n`）导致同名台多行、收藏互不相通、播放高亮互不识别（二审实测：搜「中国之声」出现 **3 行**——常听 / 央广 / YueChan 无空格变体「CNR中国之声」，radio.txt:137）。radio.txt **内部**的跨分类同名 6 例（One FM、龙广都市女性台 FM102.1、宁波经济广播 FM102.9、第一财经、扬州江都广播、阳泉交通广播；二审复核一致）。
   > 📌 已定方向（owner 已确认，见第九节决策 C）：key 保持 `c|n` 不动，STARTER 并入时按精确名去重（消掉 6 例）；无空格变体与跨分类 6 例维持现状，不引入规范化复杂度；不做 key 改纯名（先加载者定分类，行为反直觉）。

## 三、代码质量与安全

### 审计通过的项

- **XSS**：所有插值（电台名/分类/key/keyword）均过 `esc()`（index.html:238），体检增量 DOM 用 `createElement + textContent`（index.html:326-327），未发现注入面。
- **目录穿越**：`path.startsWith(ROOT + path.sep)` 兜底（server.js:67），URL 编码绕过（`%5C`、`%2e%2e`）经 join 归一化后仍被拦。
- **原子性**：Windows 下 `fs.renameSync` 覆盖已存在文件可用（MOVEFILE_REPLACE_EXISTING），tmp+rename 成立。
- **localStorage 全部容错读取**（favs/vol/last），坏值回退默认（index.html:91, 207-208）。
- Node ≥14 兼容声明成立：后端两文件未用 `?.`/`??`。

### 问题清单（按严重度）

**P1 —— 功能性缺陷**

1. **`.m3u` 导入实际不可用**（index.html:56, 100-113）。`accept` 承诺支持 `.m3u`，README:50 也写了「选择 txt/m3u 文件即时加载」，但 `parse()` 只认 `名字,http://...` 行格式。标准 m3u 的 `#EXTINF` 行解析出的「地址」是频道名（非 http，被丢弃）、纯 URL 行没有逗号（被跳过）——结果是**导入 m3u 得到一个空列表**，无任何报错。修复很便宜：parse 里识别 `#EXTINF` 并取下一行 URL、`group-title` 映射分类（update-sources.js 的 parseM3u 已有现成逻辑可以复用思路）；或者诚实地从 accept 里去掉 `.m3u`。
   > ✅ **已实证**：将 index.html 原样 `parse()` 提取到 Node，喂标准 `#EXTM3U/#EXTINF/URL` 内容，返回 `[]`（见文末核验记录）。
   > ✅ **二审独立复核：成立**（仅 csv 风格 `名,http://...` 行可存活，标准 m3u 内容全丢）。**已定修法：修 parse 支持 m3u（决策 A）**。

**P2 —— 稳定性 / 攻击面**

2. **代理上游连接泄漏**（server.js:24-30）。`r.pipe(res)` 时若浏览器侧断开（换源、暂停、关页），`res` close 只会 unpipe，上游响应 `r` 不销毁；直播流永不结束，socket 就一直挂着。多次换源重试 + hls.js 分片中断会累积 idle 连接，长时间挂机场景下 buildup。修复一行：`res.on('close', () => r.destroy())`。
   > ✅ **已双重实证**：①独立 mock 完整复刻 proxy() 路径——客户端断开 4s 后上游连接仍在（且直到进程结束都不释放）；②真实 server.js + 蜻蜓直播流实测——客户端收流 105KB 后断开，8s 后 node 进程到上游 123.60.16.94:80 的连接仍为 ESTABLISHED。直播流不会自行结束，该连接将**无限期占用**。
   > 🔬 **二审证伪一项关联假设**：「上游中途断流会打崩 server.js 进程」（`r` 无 error 监听 + 502 分支 writeHead 在 headersSent 后抛错）在 Node v24 / macOS 下**未复现**——无论正常 FIN 还是 4MB 积压后 RST，进程均存活（插桩显示该路径不触发未处理 error）。但项目声明 Node ≥14，旧版语义无保证，建议修复本条时顺手加 `r.on('error', () => res.destroy())` 与 502 分支的 `headersSent` 守卫（共 2 行，防御性）。
3. **代理上游无超时**（server.js:24）。`mod.get` 没传 `timeout`，上游接受 TCP 后永不响应时该请求永久悬挂（Node 默认 socket timeout 为 0）。建议 `timeout: 30000` + `req.destroy()`。
4. **`/proxy` 响应 `Access-Control-Allow-Origin: *`**（server.js:27）。页面本身与代理同源，hls.js 走 `/proxy` 根本不需要 ACAO。加 `*` 的实际效果是：用户浏览器里打开的**任意网页**都能让本机 8137 端口代为抓取任意公网 URL 并读取内容（本机开放代理读取面）。建议直接去掉，或仅在检测到 `Origin` 为本机时回显。
5. **`POST /api/sync` 无 CSRF 防护**（server.js:37-42）。跨源 form POST 是 simple request 不触发预检，恶意网页可反复触发同步（409 只限制并发为 1，完成后可再触发），让用户 IP 持续对外做 18 并发探活。低危但修复便宜：校验 `Origin`/`Sec-Fetch-Site` 头。
6. **【二审新增】`proxy()` 跟随重定向不复查 safeTarget**（server.js:25-26）。redirect 分支直接 `proxy(new URL(location, target).href, ...)`，`safeTarget` 只在入口跑一次——公网 URL 302 跳 `http://127.0.0.1:*/` 或内网地址时被盲跟，SSRF 防线整体绕过。
   > ✅ **已实证（真实 server.js + mock）**：直连 `127.0.0.1` 内部服务经 `/proxy` 得 403（防线正常）；经一个 302 跳板域名再指同一内部服务，返回 **200 + SECRET-INTERNAL-DATA**。叠加 P2-4 的 ACAO `*`，任意网页可读取用户本机任意监听端口的内容（本机 127.0.0.1 监听场景下即可利用）。修复约 3 行：redirect 分支对 `new URL(location, target)` 跑 `safeTarget`，null 则 403。注意 `/api/check` → `checkStream` → `request()` 跟随重定向同样无目标校验（update-sources.js:26-27，响应不可跨源读取但可作存在性 oracle），建议同批修。
7. **【二审新增，自 P3-6 升格】`safeTarget` 字符串名单可被 DNS 解析绕过**（server.js:12-19）。只校验 hostname 字面量，不解析实际 IP：任何解析到环回/内网的域名（`*.localhost`、`localtest.me`、攻击者自建域 A 记录指 10.x——即 DNS rebinding）都能过审。
   > ✅ **已实证（真实 server.js + mock）**：`crashtest.localhost`（getaddrinfo → 127.0.0.1，不在字符串名单）经 `/proxy` 返回 **200** 并取回 mock 内部服务数据。修复约 10 行：`dns.lookup` 后按解析 IP 判定（补 IPv6 私网段 fc00::/7、fe80::/10、IPv4-mapped `[::ffff:10.0.0.1]` 等）。正面结论：WHATWG `new URL()` 会把十进制 IP 字面量（如 `2130706433`）规范化为点分形式再交 `hostname`，故非点分 IP 变形**已被堵住**（实测 403）——剩余敞口就是上述 DNS 解析面。
   > ⚠️ **三审实现注记（TOCTOU）**：「先 `dns.lookup` 判定、再按 hostname 连接」的字面实现留洞——Node 连接时会再解析一次，rebinding 可在两次解析间换 IP。修法写死为 **custom lookup**：给 `http(s).get` 传自定义 `lookup` 选项（包裹 `dns.lookup`，在回调里按解析 IP 拒私网段）——校验的正是实际用于连接的那次解析；redirect 递归须把该选项透传。按 IP 直连场景另涉 https 的 SNI/证书处理，本期不需要。
8. **【三审新增】静态路由不防 dotfile，`/.git` 可读**（server.js:64-68）。`startsWith(ROOT + path.sep)` 只防目录穿越，`GET /.git/config` 正常返回。
   > ✅ **已实证（真实 server.js）**：`GET /.git/config` → **200（299B 仓库元数据）**；`/radio.txt.bak`、`/.DS_Store` 同样可读。127.0.0.1 下风险低，但 README:34 文档化了 `HOST=0.0.0.0` 局域网模式——该模式下仓库元数据对全网段可读，与 P2-4~7 同源。修复一行：拒绝路径中任何以 `.` 开头的段。
9. **【三审新增】`/api/check` 是带副作用的 GET 且 `url` 参数无上限**（server.js:43-53）。任意网页 `<img src="http://127.0.0.1:8137/api/check?url=…">` 即可驱动本机对外探活（时序 oracle + 放大：单次 GET 可挂多个 url、每 url 最长 ~6s 的串行探测），与 P2-5 同族但一审只提了 sync。修复：url 数量封顶（如 ≤4）+ `Sec-Fetch-Site`/`Origin` 校验（保持 GET，前端零改动）。

**P3 —— 硬化 / 细节**

6. ~~`safeTarget` 只做主机名字符串校验、不解析 DNS~~ → **二审实证后升格为 P2-7**（原文的理论缺口已被 `crashtest.localhost` 实测坐实）。
7. **`request()` 重定向跟随无深度上限**（update-sources.js:26-27）。上游重定向环 = 无限递归（每跳还重置 deadline）。加个 `maxRedirect=5` 计数即可（二审补充：其「无目标校验」面已并入 P2-6 修复项）。
8. **大分类体检耗时无预期管理**：799 台（中国广播）× 最多 4 源 × 每源探活 ÷ 5 并发，三审修正理论最坏为**小时级（≈2–3 小时）**——m3u8 源要发清单+分片两次请求、各受 ~6s 硬上限（timeout 4.5s + deadline 1.5s），单源最坏 ~12s（master playlist ~18s）、4 源 ≈48–72s/台，799÷5 并发即得（一审「十几分钟」、二审「48 分钟」均按单次请求计，持续低估；现实中多数死源快速失败，实际远低于此）。UI 只有递增计数没有预计时长；`renderOrder.indexOf(s)` 体检期间 O(n²)。建议状态栏给出粗略 ETA + 用 Map 索引替代 indexOf（ETA 实现勿按分钟级校准）。
9. **移动端视口**：`height:100vh` + `position:fixed` footer 在 iOS Safari 动态工具栏下有遮挡问题（index.html:10, 41），建议 `100dvh` + `env(safe-area-inset-bottom)`。
10. **无 favicon / manifest**：标签页是默认图标，与 PWA 路线冲突。一个内联 SVG data-URI favicon 几行就够。
11. **a11y 结构小瑕疵**：`role="button"` 的行内嵌真实 `<button>`（收藏）构成「按钮套按钮」（index.html:251-252），读屏语义受损；`#now` 与 `#status` 两个 polite live region 在连接期同时刷屏略吵。建议行改 `role="listitem"`（容器 list），或迁到 grid 语义。（二审修正原文表述：收藏按钮**并没有** stopPropagation，靠的是 `$('list').onclick` 委托里 `closest('.fav')` 先行命中并 return 的顺序——迁语义时需补真实的事件隔离。）
12. **【二审新增】file:// 降级模式下点「体检」会把全部台标 ✗ dead**（index.html:316-320）。`fetch('/api/check…')` 在 file:// 下必然失败，catch 空处理后 `ok=false` 落库 `s.health='dead'`——用户看到满屏死台。修复一行：fetch 失败（TypeError）时不落 health 标记，状态栏提示「file:// 下无后端，体检不可用」。
13. **【三审新增】体检途中任何 `render()` 会让后续标记静默丢失**（index.html:247, 321, 333-335）。体检期间点播/切分类会 bump `renderStamp`，增量 DOM 分支（`renderStamp === stamp`）永久关闭，之后测出的 `s.health` 只落数据不上屏，且体检结束**没有兜底 render()**——用户最终看到的标记集取决于体检途中有没有碰过页面。属正确性缺陷（比 P3-8 的 ETA 更实质）。修复一行：体检结束（含取消路径）补一次 `render()`。

## 四、Web 交互与 UI 设计

### 好的方面（超出同规模项目的自觉）

- 可访问性成体系：`focus-visible` 不删 outline、`prefers-reduced-motion` 关动画（index.html:30）、`aria-current` 用于互斥单选（语义选对了，没用错 `aria-pressed`）、`aria-live` 播报状态、`scroll-padding` 防 fixed footer 遮焦点行、`keepFocus` 整表重渲后找回键盘焦点（index.html:214-219）。
- 反馈闭环：连接中行内脉冲 ● + 底部「连接中… 源 i/N」、换源途中 pause 不改图标防闪烁（index.html:195）、全部失败给出下一步动作建议（体检/同步）、空态文案带行动指引（index.html:240-243）。
- 键盘操作：`/` 聚焦搜索（排除修饰键组合）、Esc 清空、Enter/Space 播放。
- 持久化三件套：收藏/上次收听/音量，重启即恢复，「上次收听 + ▶ 续播」是很贴心的细节。

### 待改进

1. **播放态的视觉重量不足**。「正在听」是电台 App 的第一信息，目前只有行首 ▶ + 名字变绿 + 底部一行字。建议底部加 CSS 均衡器动画条（3~4 根跳动的竖条，reduced-motion 下静止），一眼可辨「活着且在播」。
2. **搜索只支持子串匹配**。中文用户搜「zhongguozhisheng」或「zgzs」找不到「中国之声」。内嵌一张汉字→拼音首字母映射表（常用字约 400 条，几 KB）做首字母匹配，是本地零依赖完全可做的杀手级体验。
3. **「地方」分类 484 台平铺**，只能靠搜索。数据里地名前缀天然存在（安阳/包头/保定…），按省份/城市分组或加右侧字母索引条会显著提升可达性。同理「中国广播」799 台也值得二级分组。
4. **无浅色主题**。CSS 变量已就位（index.html:8），加一组 `prefers-color-scheme: light` 覆盖成本极低，白天场景友好。
5. **footer 控制条偏素**：音量无静音按钮、无百分比、`#vol` 拖动时无即时数值反馈；窄屏下 badge/srcs/health 挤一行，可媒体查询隐藏「N源」。
6. **分类 chip 无数量提示**，加个 `音乐 45` 式角标能帮用户预判列表规模；chip 横向滚动无渐隐提示可滚动。
7. **同步期间无进度感**：约 1 分钟只有文案，状态栏做个不确定进度条（CSS 动画）心理感受完全不同。

| 早期结论 | 判定 | 推敲依据 |

### 新识别的架构债务

1. **收藏身份的漂移脆性（有实证，~15 行）**：favs/last 的键是 `c|n`，而流地址才是电台的耐久身份。对策：favs 条目同时记录该台任一源 URL，加载后按 URL 回绑（名字变了收藏仍在、孤儿键可回收）。这与 sidecar 以 URL 为键的方向自然收敛为一条身份公理：**URL = 持久身份，名字 = 显示层**。✅ **owner 已拍板（2026-10-12）并入本期，已列入第八节 D 组清单**。
2. **拆分的模块契约**：纯 script + 全局共享若无所有权约定，会把一个 355 行文件变成四个互相伸手的全局文件——那是换汤不换药的耦合。契约：player 拥有 audio/hls/播放态，app 拥有 stations/渲染/收藏，sync 只编排；跨模块只走暴露接口 + 单一 render 入口。另注：用经典 script 而非 ES modules 是硬约束（file:// 下 module 加载受 CORS 限制必挂），这一点使「零构建拆分」的方案空间比看上去窄，值得写明防止后人误改。✅ **owner 已拍板（2026-10-12）并入本期，契约已写入第八节 A 组清单**。
