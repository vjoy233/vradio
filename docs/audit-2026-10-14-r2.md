## 三、新发现：P2（2 项）

### P2-1 上游畸形 `Location` 头 → 未捕获 TypeError → 整进程崩溃（三处同款裸 `new URL`）

`new URL(畸形绝对地址)` 会抛 `TypeError`（如 `Location: http://[` 未闭合括号、`http://host:badport/` 非法端口）。以下三处在**响应回调内**裸解析重定向头、无 try 保护——回调内的异常即 `uncaughtException`，仓库内无兜底 handler，Node 默认行为 = 打印栈后退出进程：

| 位置 | 影响面 |
|---|---|
| server.js:44（`proxy()` 重定向逐跳复查） | 正在听的代理流 + 整个服务 |
| server.js:137（`npStart` 曲讯旁路重定向） | 同上 |
| update-sources.js:105（`request()` 重定向） | `npm run sync` CLI 与 `/api/sync` 服务进程 |

触发条件 = 任意被代理/探活/同步的上游返回畸形 Location（恶意流服务器可主动构造；故障 CDN 偶发）。本项目威胁模型把上游当不可信输入（SSRF 双护栏、HTML 判活、logos.txt 引号拒收都是这个口径），重定向头应同权对待。影响 = 可用性（进程当场死），非数据损坏（store 原子写、同步有 .bak）。

**修法**（各 ~3 行，共 9 行）：三处把
`safeTarget(new URL(loc, base).href)`
包成 `let u; try { u = new URL(loc, base).href; } catch (_) {}` 后再 `safeTarget(u)`，解析失败按「重定向目标拒绝」走既有 403 / deadAt 分支。可选：test/smoke.js 加一条回归（本地起假上游回 `Location: http://[`，断言服务不崩、返回 4xx/5xx 而非连接重置）。

**附带（前端同款，P3 级）**：player.js:180 `new URL(raw).href`（proxyBase 计算）——导入的畸形 URL（parse() 只验 `http` 前缀）会让该台点播抛错、UI 卡「连接中」且看门狗不武装（无任何媒体事件）。修法同款 try，失败即走 `onFail` 顺延。可并入本项顺手修。

### P2-2 三审 B3（ended 自愈缺 halt 守卫）**声称已落地、实际未落地**

三审第十节声明「审计代码类建议当日落地完毕」，但 B3 不在 R2/R3 落地清单里，代码实况：

- player.js:47 `el.addEventListener('ended', () => { if (this.station && !this.connecting) this.retryOrNext(); })` —— **无 halt/暂停守卫**（看门狗路径 player.js:231 有 `isPaused()` 双保险，ended 路径没有对齐）；
- 更深一层：player.js:239-242 `retryOrNext()` 的「先重连当前源」分支直接 `load()` → `audio.play()`（player.js:196/198 无条件 play），**完全绕过 halt**——`next()` 的守卫（player.js:164）只挡 i>0 的级联续摊，够不着重连分支。

可达场景：多标签让位竞态——本页因他页开播被 `pause()`（halt=true），恰逢流 ended（或 ended 与 pause 竞态交错）→ `retryOrNext` → `audio.play()` 自我复活 → `playing` → 广播 `'on'` **反杀刚开播的对方标签**——正是 AIbot P2-1 halt 机制要堵的 ping-pong。单标签下用户暂停页也可能被 ended 竞态复活。

**修法**（1 行）：ended 监听改为 `if (this.station && !this.connecting && !this.halt) this.retryOrNext();`（resume 经 heldNext 调 retryOrNext 时 halt 已置 false，不受影响；watchdog 路径已有双保险，可不重复加）。

**流程警示（比 bug 本身更值得记）**：三审的「落地完毕」是 blanket 声明而非逐条列举，本轮逐条复核了三审全部代码类建议（B1 双 rebind / B2 tag 两处 / C1-C5 / A1-A6 / R1——**除 B3 外全部属实**），唯一漏网即此条。后续审计的落地声明宜逐条点名，或以 R2/R3 式清单收口。

## 四、新发现：P3（3 项）+ 已拍板待落地（3 项）

### P3-1 `/api/check` 与 `/api/nowplaying` 缺方法校验

其余端点已全部收口：`/api/sync`、`/api/mystation` 仅 POST，`/api/store` GET/POST + 其余 405，`/proxy` 仅 GET（405），静态仅 GET/HEAD（405）——唯这两个 API 任意方法（POST/PUT/DELETE）都会执行探活/建旁路连接。`crossOrigin` 已挡跨源驱动，实际风险很低，属一致性/纵深缺口（audit A4 与 AIbot P3-4 的收口动作没扫到这两个）。**修法**：两处入口加 `if (req.method !== 'GET') return json(405, …)`，smoke 可顺手各加一条断言。

### P3-2 footer `#nowline` / `#song` 可点但键盘不可达

「回到正在播」（app.js:999）与「本台歌曲历史」（app.js:988）都是 div + onclick，无 `tabindex`/`role="button"`/Enter 处理——键盘用户无法触达这两个功能（列表行、收藏钮、面板按钮都已有完整键盘路径，就这两处漏）。**修法**：index.html 加 `role="button" tabindex="0"`，app.js 对应 keydown Enter/Space 触发同款 onclick 逻辑（各 ~4 行）；`#song` 空态（hidden）时 tabindex 由 `[hidden]{display:none}` 天然移出 tab 序，无额外处理。

### P3-3 ⚙ 面板「添加电台」表单无 Enter 提交

同面板内备选源追加输入框有 Enter 触发（app.js:1129-1134），`#mAdd` 的 mAName/mAUrl 没有——同面板交互不一致，键盘流添台要专门 Tab 到按钮。**修法**：`#mAdd` 上加同款 keydown（Enter → 触发 `#mAddBtn`，~5 行）。
