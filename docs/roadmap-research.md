## 硬边界（筛选前提，来自 AGENTS.md / owner 既往拍板）

1. **零依赖、无构建**：只用 Node 内置模块 + 本地 hls.min.js，7 源码文件形态。
2. **国内直连**：运行时不依赖任何境外可达服务；同步期用镜像（AlonDrilich/radio-playlists）是既有合法模式。
3. **file:// 降级形态**：依赖代理的新功能在降级下不可用属正常，口径与现状一致。
4. **EPG 已砍**：owner 实测拍板移除（bfdc917），不再回头。
5. **模块契约**：player 拥有播放态、logos 拥有台标、app 拥有列表/渲染，sync 只编排——新功能不得破契约。

## A 档：低成本低风险，建议优先

### A-1 断流自愈 + 变体成功记忆

> **2026-10-12 三轮修正问题陈述**：现状并非「只能手动换台」——player.js:79 `audio.onerror` 闭包在整个播放期存活，中途 error 事件（含 HLS fatal→onFail，player.js:91）已会自动顺延 `variants()`。**真正的缺口**：① 静默挂起（stalled/服务端正常断连 ended）不触发自愈，这才是「播一半断了」的主场景；② 无「先重连当前源一次」策略，直接顺延；③ 无成功源序号记忆。实施者勿重复造 error 级联。
- **功能**：补 stalled/ended 看门狗 → 自动恢复或顺延；成功源序号按 URL 持久化，下次点播从它试起。
- **验收口径**：播放中拔网线/服务端杀流，N 秒内自动恢复或顺延到可用源，全程无手动干预。
- **成本**：低。player.js 几十行，不碰模块契约（世代令牌机制天然兼容）。
- **风险收益**：风险接近零；收益直击最高频的真实失败场景。

### A-2 「添加自定义电台」UI

> **2026-10-12 三轮补强动机**：现状「导入列表」是会话级的——app.js:415-421 导入只 `applySources` 不落盘，刷新后 `reloadMain` 重拉 radio.txt + my-radio.txt，导入的台即丢。个性化持久化目前只有手编 my-radio.txt 一条路，本项是刚需闭环而非锦上添花。
- **功能**：对话框输入名称 + 流地址 + 分类 → 先打 `/api/check` 探活（假流拦截复用现有验收）→ 存活才写入 my-radio 个人层。
- **解决**：把 my-radio.txt 从「手编文件」变成产品功能。
- **成本**：低到中。前端一个弹窗 + server.js 写文件接口。
- **实现护栏（三轮补）**：① 写盘 tmp + rename 原子替换（与前端 reloadMain/同步重并并发，半写文件会被 parse 进去）；② 内容护栏：台名去逗号/换行（radio.txt 格式硬约束）、单台源数与文件总量封顶；③ 写接口按既有口径复用 crossOrigin 防 CSRF。此前文档写的「防路径穿越」不准确——文件名固定无用户可控路径，真正的面是内容注入与并发。

- **风险收益**：零风险；收益中（随机抽到的可能是死台——可先排除 health:'dead'）。

### A-5 键盘快捷键

- **功能**：空格播放/暂停、`/` 聚焦搜索、←→ 在收藏间切换。

## B 档：中成本，价值取决于 owner 取舍

### B-6 正在播曲讯（Now Playing 元数据）——同类第一卖点

> **2026-10-12 拍板：进本期，直接上完整版（ICY 旁路解析），不走便宜版过渡。**
> **2026-10-12 三轮补三项方案缺口**：
> ① **协议覆盖预期**：ICY meta 只存在于 Icecast/Shoutcast 形态的 mp3/AAC 直流；HLS(m3u8) 内没有 ICY（央广系全走 m3u8，结构性无曲讯——「国内台大多无元数据」按协议分布理解，非概率问题）。欧美台多 Icecast mp3 直流，是曲讯的主受益人群。HLS 理论上可带 ID3 timed metadata（hls.js 可暴露），本期不做、不承诺。
> ② **解析路径取舍（修正 review 的成本判断）**：走 /proxy 播放的台流本就过服务端，proxy() 内搭车 tee 解析零额外上行连接——但**实际覆盖很小**：会被逼到代理级的基本是 m3u8（央广 ngcdn 系），而 m3u8 无 ICY；mp3 直流不涉 CORS 天然走 ① 级直连、不过代理。结论：**旁路第二条连接是主路径**（对直连播放中的台，服务端自开连接读流解析），proxy 搭车作为顺手项（sniffer 函数共用即得）。旁路连接的计数、超时、失败静默都要独立于播放路径。
> ③ **轮询模型（定稿）**：ICY meta 是流内 inline 的，保持旁路连接**持续读**即可近实时拿到歌曲切换，优于周期重连（只能拿到连接时刻曲名）。内存有界（环形读取），切台/停止即关连接，页面不可见时降频或暂停读。
> ④ **安全回归动作**：`/api/nowplaying` 是带副作用 GET（驱动服务端开上行连接），与 /api/check 同类——复用 crossOrigin 防跨源驱动 + safeTarget/guardLookup 双层校验 + 重定向逐跳复查 + 并发连接封顶，交付时过 docs/review.md G 组清单。

- **功能**：完整版——服务端旁路读流解析 ICY meta（mp3 ICY interval 二进制解析 ~150 行），`/api/nowplaying?url=`，前端只对正在播的台取曲讯；曲讯顺手写进 MediaSession（锁屏曲名，零成本增值）。
- **解决**：听音乐台时「这是什么歌」是刚需；台标之后的信息层级。
- **成本**：中高（解析 + 连接生命周期管理 + 安全回归）。
- **风险**：国内台按协议无 ICY（显示为空即可，不报错）；欧美台多 Icecast 直流是主受益面；file:// 不可用（口径一致）；旁路连接的带宽/句柄需封顶。
- **收益**：同类产品最大体验差异点，候选下一个「台标级」功能。

> **2026-10-12 拍板：进本期，但改用便宜变体**——打开页面时后台静默体检「收藏 + 最近播放」范围的台（几十个，带宽可控），复用现有 Sync.health 管线与 radio.health 落盘，**无服务端改动、无新接口**；手动全量体检按钮保留。原服务端定时方案（/api/health/delta 交接）留档备查，下文未改写。
> **2026-10-12 三轮补互斥与时机**：① Sync.health 是 UI 态编排（按钮文案/共享 abort 标志/状态栏文案，sync.js:27-57），静默版不能直接复用入口——需抽 scope 参数 + 互斥规则（手动体检启动时取消静默版，静默版不碰按钮与状态栏）；② 启动时机在首屏渲染之后（几十台 × 阈值字节别拖首屏）；③ file:// 下无声跳过（现有 health 会写状态栏提示，静默版要绕开）。

- **功能**：server.js 定时任务，收藏 + 最近播放的台优先复查（范围限定），结果经 `/api/health/delta` 类接口交前端开机合并落盘。
- **解决**：死台标记目前靠手动点「体检」，自动消失体验更好。
- **成本**：中。探活逻辑已有，难在架构交接（health 落盘在前端 localStorage）。
- **风险**：带宽（必须限范围）；与手动体检的写盘协调（FIFO/TTL 合并语义要定义）。
- **收益**：中。
