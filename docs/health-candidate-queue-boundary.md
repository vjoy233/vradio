# 安卓新增台审查队列：边界

本阶段只保存材料，不实现恢复或自动消费。两条同步路径在写主库前追加完整批次至私有 `health-candidates.json`；包括批次 UUID、路径、旧/新全文 SHA-256、每条候选原行及分类和名称。批次集合自身有校验哈希；解析、校验或原子写失败时中止主库发布。旧批次不删除；容量无限增长，磁盘不足会阻断更新，需设计有界归档与安全确认后才能上线消费。原子替换不保证掉电持久化或跨进程互斥。

轻更新既有新增判定为分类|名称，端内同步为全局名称；健康状态实际身份是源 URL，现有增量体检按名称匹配、截取 500 且不具备持久确认、冲突仲裁或按批重放。队列因此保留全部匹配原行及多源，不声称这些名称就是稳定身份。分类移动、同名跨分类、源变化不等价于真正新增身份；个人层、隐藏/禁用源及启动加载后的实际装配还需明确仲裁。欧美两节按既有策略排除。写前记录意味着失败或中断可留下未发布批次；新旧 hash 仅作证据，不代表发布成功。消费者未来必须核对实际库 hash、批次状态、URL 身份和用户数据，安全处理重复及部分进度，不能盲目重放。旧版已丢失的候选不可推断，现有范围警告仍保留。队列不接线消费，也不宣称恢复完成。
