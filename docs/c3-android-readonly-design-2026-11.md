# C3 Android 只读接入设计提案（草案，默认 No-Go）

本文件是基于 PR #75 的设计提案，不是产品发布许可、契约冻结、功能实现或测试/实测证据。当前仅有隔离 sidecar 解析器；不接加载、UI、播放、联网、持久化或正式发布。现有发现页为本地派生，不将第三方候选混入。实施方案 D.1.2 所列设计门必须完成、独立评审后才进入实际接线；本提案不能绕过 C3 测量、许可、真实试听和发布门禁。

## 建议边界和顺序

1. 先固定跨端 schema、严格字段类型、排序/去重、分类映射、URL 策略及 manifest 绑定语义，并用共享黄金样本核对 Web/Android；#75 解析器仅作实验，不能推定契约已冻结。无效、超限、版本不支持或不一致一律失败关闭。哈希只证明匹配，不证明来源或许可。
2. 推荐正式投递采用独立快照，不混入 radio.txt、四资产协议或用户备份；无已审查生产快照时不随包携带数据。受控来源固定后一次确定不可变 commit，pointer、manifest、代数据均按同一 commit 获取，限制路径为严格 64 位小写十六进制，校验 manifest 长度与原始字节 SHA、schema、UTC、来源和安全 URL；不以分支 HEAD 各次读取或时间戳判断一致性。读取前必须限制输入字节（sidecar 512 KiB、manifest 4 KiB、最多 300 项仅为现有解析实验上限，须跨端确认）；限长应在流读取阶段实施，而非先无界读完再检查，并设置总超时。本提案不授权实现联网或打包真实 sidecar。
3. 推荐私有 filesDir 内同文件系统 staging 写齐并校验、安装不可变代后最后切 current/previous；单写者串行。启动逐代验证 current 然后 previous，远端 pointer 与其引用文件均绑定同一已冻结 commit，并验证该 commit 实际包含所引用的两代；若远端 previous 缺失，可回退本地已验证旧代，明确这是跨 commit 的本地离线回退而非远端混代。超时预算必须为 previous 留有余量，同代重发不得覆盖原 previous；指针损坏不猜代，首次失败安全空态；缺失、损坏、超限、版本不支持、超时均不得影响主库、播放或个人数据。原子提交与恢复依赖底层文件系统语义和故障注入验证，不能仅凭 rename 宣称断电安全。开关关闭时不读取、不渲染、不联网；明确不可用与回退状态，禁止把 fixture 当真实内容或证据。
4. 默认关闭独立 C3 开关，不能复用既有本地发现总开关以避免改变原功能；测试可注入开关而非持久用户设置。设计阶段不指定生产开关覆盖入口，发布前须审查 release 构建关闭策略、远程投递路径和回滚演练。

## 展示和生命周期推荐方案

- 数据只读展示与现有本地派生层清晰区分，不能将 sidecar 伪装成主库或改变原有发现组排序。实验 fixture 如被未来批准，只能存测试源集、离线构建并明确标注，无真实电台/链接，不进入 APK 的正式发布路径。
- 推荐试听采用临时单源 Station、明确用户点击才发起，并提示电台、重定向及 CDN 可能获得 IP 和消耗流量；不自动探活、不预取台标。试听替换当前播放，停止试听后不自动恢复原台，以免制造隐式联网。离线实验不启用试听。现有 `PlayerHolder` 使用普通 OkHttpDataSource，不能假定拥有探活侧 GuardDns 和逐跳安全校验；须先实现并验证试听的所有连接级安全策略，覆盖重定向、HLS 播放列表及分片、DNS 重绑定和网络策略并评估兼容性，否则试听禁用。
- 推荐试听不写最近、质量、统计、收藏、成功源记忆、台标缓存、歌曲历史及音量记忆，不启动 Timeshift 录制或附加曲讯/台标网络请求；通知和 MediaSession 仅反映当前临时会话且不得经 artwork 引发额外请求。但这不是当前能力：`AppVm.startPlay` 已无条件调用 `lib.recordRecent`、可能 `logos.prime`，`PlayerHolder.onAir` 对多源写 srcmem，播放链其他监听亦有副作用。必须先实现有会话令牌的试听上下文并贯穿全部出口、暂停/重试/切台/异步迟到事件，逐出口证明隔离；不得绕开 `startPlay` 就宣称无副作用，也不得破坏正常播放回调。若无法证明则禁用试听，不以污染现有数据换取接线。
- 推荐不在临时候选展示收藏星；先明确加入个人电台，再使用既有收藏。查重按原始 URL 精确匹配主库所有源与个人层，命中提供定位/收藏而非创建克隆，同名不合并；休眠收藏 URL 要参与回绑检查。未命中经用户确认后复用个人层安全校验、网络策略、受控探活、清洗、限额和写入流程，按实际结果反馈，重复点击和并发须串行与幂等，未知提交先对账。仅命中休眠收藏时仍须先成功加入个人层并重载回绑，再显示收藏状态。MyRadio 当前只对个人层查重、预检不保证最终 UTF-8 字节/行数严格达标、以 Boolean 混合失败原因；须先实现最终输出 UTF-8 字节与行数校验、原子提交和明确失败类型，不能直接视为满足完整设计；Web 归一化 URL、Android 原始 trim 的既有不对称不得单侧改变。sidecar 删除或换代不得删除已加入台与收藏；写失败不得宣称成功。持久 provenance 暂不引入新键或改备份契约。
- 暂不批准 UI 接线：现有发现卡点击直接进入真实播放器，缺少隔离试听及统计、收藏、个人层身份设计；简单挂默认关闭开关不能证明上述副作用安全。

现有 Web sidecar 流程并无试听，仅个人层查重，主库（包括备用源）已有 URL 仍可能重复加入，亦未实现休眠收藏匹配；本节是未来目标，不声称双端现状一致。当前 Web parser 存在 String 强制、跳过和截断，Android 实验解析器倾向严格整批失败，语义尚不一致。推荐冻结统一的严格字段类型、整批失败、UTF-8 字节及项数边界、URL 与重复语义，以共享 fixtures 验证；两端修复、评审和测试前禁止开启 C3。任何跨端行为和契约变更须先共同冻结和测试，不得由 Android 单边变更 Web 持久协议。

## 先决条件与未来验收

- 测量、许可、人工试听、国内直连及成品门禁按对应 C3 决策执行；缺证据即 No-Go，测试 fixture、JSON 中自报来源、哈希、模拟听取均不是证据。
- 跨端格式及行为测试覆盖无效/错误类型、边界值、多字节、截断/超长流、hash/版本/代错配、重复、非法 URL；验证默认关闭零读取零网络，关闭后原页面与本地发现不变。
- 存储测试覆盖缺失/损坏/写入失败/中断及回退、同 commit 远端缺代与本地跨 commit 已验证回退，证明不影响主库和用户数据；对真实文件系统分别验证进程中断与断电假设。生命周期测试覆盖播放、暂停、切台、统计、收藏、显式加入、重复/冲突和身份漂移；加入与同步、导入、并发重复操作交错时验证最终查重、幂等及数据保留；各类动作负面断言无隐式写入。
- UI 与设备测试覆盖开关关闭、空态/错误态、无障碍、列表 bounds 与无意联网；JVM 测试不能代替设备验证。生产合入/打开前完成跨端审查、发布和回滚演练，并单独记录证据；本 PR 不宣布这些条件已经满足。
