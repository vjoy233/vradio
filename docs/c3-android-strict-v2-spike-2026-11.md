# C3 v2 Android 离线解析实验

基于 #89 的 a6d63808d349e8c6fff689f246d311349798fb63；提案未冻结，实验代码只在 JVM 测试源集，不改变生产解析、网络、文件、UI 或开关。测试从共享 generated fixture 解码原始字节，检查完整输出、拒绝、边界和真实 SHA-256；pointer 的代选择与本地撤销结果仅为测试环境模拟，可选上游 commit pin 为 fixture 注入，不是来源真实性证明。URL 仅检查格式，回环地址可合法通过，绝非 SSRF 防护。

## 与现有实现及规范的差异和限制

- 既有 v1 消费器不被复用或替换；实验解析器拒绝重复键、BOM、无效 UTF-8、非配对代理项、未知字段和不符合协议的数值，整代失败，不执行跳项或强制转换。
- JSON 数字仅接受可表示为 Long 的整数字面量，不接受 2.0 或指数形式；提案称整数但未明确数字字面量等价口径，实验暂与 Web 统一采用整数字面量，待评审冻结。URL 路径和查询的原样方括号同样保守拒绝，虽然 RFC 3986 将其列为保留字符；百分号编码仍可通过。parser 使用完整 ByteArray 入口，已检查长度但不提供有界流读取，因此不满足未来网络读取时立即中止的要求；实验主动将 JSON 容器嵌套限制为 3 层（合法 schema 最大深度）并测试 3/4/10000 层，该上限是实验护栏而非已冻结提案约定，其他资源消耗未全面验证，不能直接用于不可信生产数据。
- 修正 P1：delivery revision 属于投递仓库，与 sidecar 的上游 commit 不同，绝不直接等值比较。实验 generation 的可选 expectedUpstreamCommit 仅在显式给出时比较上游声明，缺失或 null 不执行该比较；无论是否指定均返回 provenance=unverified。delivery 仓库/revision/path 的可信获取与绑定、代的存在证明、连接安全、签名、撤销策略和本地缓存均未实现。旧 pointer 样本中的 cross-commit 仅模拟显式上游 pin，不能证明远端 previous 同 delivery revision。SHA 仅证明原始字节一致。
- 共享样本并不穷尽 URL/UTF-8 对抗；回退选择和撤销模拟写在测试中，并非验证生产回退实现；Web v2 消费器尚无实际运行对比。仅在本机 JVM 运行不代表 Android 设备、跨端一致性、来源/许可或真实试听已验证。C3 继续 No-Go，需独立安全评审与设备验证。
