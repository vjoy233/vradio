# C3 投递成员认证与版本策略（推荐方案，草案）

## 状态和范围

此文仅提出未来方案，不是现有产品配置、实现、授权、上游来源证明或发布决定。基于 #73 的 `86f29d85caadfcaafbed966231ea16c955f098ab`；#77 的安全发布设计、#86 的 v2 合同草案、#94 的离线假体均为并行未合并工作，需分别评审；本方案与其证据门、离线生成/显式发布隔离及只读消费相补，不修改其门槛。**C3 仍为 No-Go**：真实两轮复测、可证明国内直连、真人试听、许可和其他既定门禁没有在此取得；自动探活或投递认证不能替代它们。

## 现状与问题

- `features.js` 的 `discoverySidecar` 默认 false；`app.js` 在开关打开后使用相对 `discovery-snapshots` 路径。`discovery-sidecar.js` 对指针、manifest、原始字节长度及 SHA-256 做本地一致性检查，当前代失败尝试上一代；它没有认证发布仓库、固定 Git 修订或 tree 成员关系。普通 HTTP LAN 上指针、manifest 与数据均可被同一攻击者一起替换；哈希只说明互相匹配。
- `discovery-publish.js` 实验发布器生成独立代和指针，输入字段/自报 `license` 不构成来源或许可证明。#94 离线 fake 只检验同一模拟会话的行为，不认证 GitHub，不可用其测试结果宣称已有真实适配器。`upstreamCommit` 与这里的 **delivery commit** 各有含义，不得等同。

## 推荐信任配置与检验

1. 应用每个版本自带、受应用正常发布流程保护的配置：精确 GitHub 仓库 owner/name、完整不可变 delivery commit ID、允许读取的精确相对路径集合和资源上限；配置与发布包一起审查、版本化。此处故意不指定真实仓库、commit、路径或密钥：当前尚未选定并认证实际配置，不能凭空填写。不得从待验证指针、网络 JSON、普通用户输入或同一不可信缓存中取得这份信任配置。
2. 用 GitHub HTTPS/TLS 受认证连接访问固定仓库、固定 commit 的对象和 tree，从 commit 到 tree，再逐层绑定精确路径到普通 blob，对原始字节进行对象 ID/内容关系核验；所有读取绑定同一个已验证 commit/tree 会话，不能跨分支、跨 commit 或两个会话混合。拒绝不在白名单的路径、`..`、歧义路径、符号链接、gitlink、非普通 blob、缺对象/类型错误/响应过大、对象哈希不符、非预期重定向及未经认证的返回。适配器须在目标 Git 对象格式与平台上实现并测试完整树链，不能以 GitHub URL 或响应内自报 SHA 代替成员证明。
3. 仓库身份和固定 commit 的可信性来自应用版本配置及应用发布渠道；传输信任 GitHub 服务按请求返回正确内容、平台 TLS 根证书/域名验证及本机安全。Git 对象/路径校验约束字节属于所固定 tree；如果应用包/配置、GitHub 账号/服务、CA/TLS 环境或终端被攻陷，不承诺抵抗。GitHub HTTPS 不是独立签名证明；仅凭合法 HTTPS、任意 commit 或自报字段不能证明对象属于被授权 tree。实际适配器、身份解析和重定向策略需单独实现及审查，现阶段不存在已验证的生产连接。
4. 树成员认证只证明该固定投递版本的指定文件和字节一致，**不证明上游抓取真实、内容正确、流许可、真人试听、国内直连或长期可播**。真实上游来源、许可和两轮/试听仍按独立证据门核验；内容哈希同样不证明任何这些事实。生成/发布端依旧遵循 #77 所述受控单写者、固定路径、崩溃恢复；此消费侧建议不把生产写权限扩给客户端。
5. 现有 current/previous、大小和哈希校验仍可作为成员验证后的第二层结构/完整性与损坏回退；允许的每个指针、manifest 和数据成员都必须来自同一个固定 tree 且在白名单内。若指针引用白名单之外或不同 tree 的代、任一关键对象未认证或无可验证候选，失败关闭为空，不得静默退回未认证 v1、任意 URL 或主库写入。v2 模式与 #86 为提案关系，格式/具体路径须实现前联合冻结，不声称现有 v1 已实现该策略。

## 修订、撤销及离线边界

- 更新数据的 delivery commit、路径或仓库，需要随新应用版本发布新的受控配置；旧版本继续固定旧配置，不从可变远端分支自动升级信任。发布前确认 tree 内所有文件与白名单、成品及独立证据对应；两者不一致则不发布。更新不是生产发布门的豁免。
- 撤销受污染 commit、仓库或路径：发布新应用版本移除/替换配置，必要时默认关闭 C3；升级后清理或隔离与旧配置绑定的缓存，避免新版本继续使用已撤销内容。缓存键至少含仓库、commit、路径及应用策略版本；缓存命中仍验证字节和成员证明，配置变更或验证失败不得跨版本复用。旧版离线设备、不可达或不升级的客户端无法收到撤销：**不支持即时全局撤销**。
- 离线仅可使用本应用版本已验证、未被该版本本地策略禁用的缓存；没有可验证缓存则安全为空。离线无法得知远程撤销或新版本，可能展示陈旧内容，不能宣称实时新鲜或已撤销；UI 应明确离线/最后验证时间（若可可靠记录，不把本机时间当可信时间）。可定义本地保守过期后空态，但时钟可改、过期不能证明实时撤销。
- 不承诺 anti-rollback：旧应用包、旧设备或被恢复的旧本地状态仍可能接受它们原先固定的旧 commit；TLS、哈希和单次 tree 校验不提供全局单调版本保证。若未来需要抵抗回滚或即时撤销，须另行设计受信持久单调状态、在线新鲜度/撤销服务等，并明确其离线、隐私和故障代价。

## 未来实现验收（均非本 PR 已完成）

- 离线可控 fixture：错误仓库/commit、伪造响应、错误 tree/blob、跨 commit 与跨 session 混用、路径穿越/符号链接/gitlink/重复路径、缺对象、超限和错误重定向均失败关闭；完整单树正例按固定配置通过。并发和请求重试不得混树；损坏 current 时仅可回退同一授权 tree 中白名单 previous。
- 集成本地 HTTPS 假服务验证证书/主机失败、重定向约束、超时、截断和大小限制；真实 GitHub 集成需在另行授权的可控环境核对可信配置及实际 API 行为，避免把假服务或假 provider 当真实认证。浏览器/Android 的 TLS、缓存、网络权限及各自实现分别实测；不得放宽 SSRF/连接护栏。
- 测试缓存与策略版本隔离、升级撤销/清理、离线空态与陈旧提示、旧版不能收到撤销、回滚旧应用不保证防护；保留既有主库/个人数据字节不变和默认关闭测试。对目标平台的 Git tree 对象校验及错误处理做独立安全 review。
