# Web 候选试听：安全设计与离线验证草案

状态：**设计草案，未实现、未验证、不可发布**。基线为 C1/C3 Web 整合 PR #88 的 `40f18da2d6751cfae58d536271ed397fee74b4bf`。本文件不改变任何生产代码、开关或资产。Android 已发现同类安全缺口，本草案只讨论 Web，不代表 Android 已修复或通过验收。

## 目标与禁止事项

- 第三方候选只在显式启用实验开关后可试听；新增开关默认关闭，现有生产默认值不改。沿用既有 Player、其播放/暂停/重试与统计生命周期，不另造播放器。
- 试听不调用写个人列表的 API、不改 `my-radio.txt`；只有明确的独立「加入个人电台」动作可在探活成功后写入。试听允许正常播放生命周期所需的最近、音量、源记忆与统计等写入，不应误说试听完全无持久副作用。
- 不以 sidecar 格式校验或哈希一致声称来源可信、目标安全或媒体内容可信；发布仍受独立生产证据门约束。

## 已识别阻断

1. `discovery-sidecar.js` 的 URL 格式校验只要求 HTTP(S)，不证明公网；输入可包含内网地址、重定向目标和攻击者控制的 HLS 清单。
2. `player.js` 当前先尝试浏览器直连，代理只是兜底；浏览器的音频、HLS 清单和子资源直连无法经过服务端连接级 DNS 检验。候选播放仅做前端字符串过滤不能防 DNS 重绑定或重定向。
3. 现有 HLS 代理 `xhrSetup` 用 `includes('/proxy?url=')` 判断是否已代理，恶意 URL 可伪造该子串；单个初始 `proxyBase` 不足以表达多层清单及服务端重定向后的相对 URL 基址。原生 HLS 路径也未保证所有子资源经过代理。
4. 独立只读复审已实证 IP 字面量缺口：`safeTarget` 接受 WHATWG 规范化后的 `http://[::ffff:7f00:1]/`，Node 的 `http.get` 对该字面量不调用 `guardLookup`；临时回环 fixture 返回 `200 LOCAL`。该结果证明此映射形式可触及回环，不代表其他地址形式已逐一验证；其修复由独立任务处理。CGNAT 和其他特殊地址仍需真实验证。`server.js` 当前代理跳转枚举不含 308，需明确并验证跳转策略。已有 `VR_TEST_GUARD=1` 同时替换目标校验和 DNS 校验，不可作为生产防护通过的证据。
5. `App.rebind`、`resolve` 先按分类与名称组成的 key 查找，再按 URL 查找；临时候选撞名可误绑定，候选 URL 命中已有台的非首源、禁用源、隐藏台或多个台时不得静默生成不同身份或绕过现有策略。

## 建议设计（待证明）

### 身份、动作与生命周期

- 单独展示试听与加入按钮；事件处理再查当前有效候选，且再次检查实验开关；关闭、失效或 file:// 时安全失败，不降级直连。
- 首先以**原始、精确 URL**查找现有台的全部源（包括非首源、禁用源和隐藏台），不按名称推断身份。多个匹配为歧义，拒绝并提示；单个匹配须遵守隐藏与禁用等现有策略，不应借候选入口绕过。具体匹配后使用已有台的哪种动作和呈现须评审冻结，不能默认把禁用源当可播源。
- 对无匹配候选使用不会与现有分类/台名 key 冲突的显式临时身份；所有持久身份仍锚定原始 URL，绝不存代理 URL。改造候选的最近/收藏解析及回绑，避免 key 优先错绑；增加后按 URL 回绑已有个人台、改名/分类变化时不重复。候选的收藏入口、刷新后休眠与重新解析应有明确 UI 与规则；不能只增加临时 station 对象就宣称生命周期完整。
- 试听由 `App.startPlay` 进入现有 `Player.play`、原有 `onstate`/`onqos`/ListenStats 与质量事件；验证播放、暂停、切台、失败、自愈与会话终止。保留身份 URL 和真实源 URL，代理路径仅为传输细节。
- 用户确认加入才调用现有 `/api/mystation` 探活和串行写入；失败、超时结果未知及重复 URL 沿用并验证现有语义。试听和 UI 重渲无任何添加请求。

### 候选会话强制代理

- 在**现有 Player 内**增加不可因刷新、重连、错误级联、暂停恢复、来源切换而丢失的会话级传输策略；候选仅允许经同源受控代理请求，禁止直连和蜻蜓转换直连。已有电台行为不变。切换会话时不泄漏策略或旧异步回调。
- 对候选禁用无法证明全链代理的原生 HLS 回退；缺少受支持的受控 HLS 实现时明确失败，不自动退回浏览器直连。检查曲讯旁路、台标、MediaSession artwork 等相关网络副作用，不能有候选 URL 或其他攻击者输入驱动的未受控网络访问。
- HLS 必须覆盖 master、variant、分片、密钥、字幕、备用音轨及实现支持的其他网络资源；严格结构化校验同源代理路径，绝不能用子串判断是否已代理。拒绝非 HTTP(S)、凭据、无效 URL 和不受支持的加载路径。
- **待原型证明**：服务端代理跟跳后当前不向客户端暴露最终上游 URL；每一层清单的相对引用均须基于该层最终 URL 解析，且包括跨域绝对引用。可评估服务端受控重写各层清单，或受控 HLS loader 获取并使用可信最终基址并拦截所有请求；均须审查完整 HLS 功能、URL 解析与凭据、失败回收。未经端到端证明不选定方案，不可假定修改 `xhrSetup` 一处即安全。

### 服务端网络边界

- 初始目标和每次重定向都执行严格 HTTP(S) URL、无用户凭据、公网地址校验；以实际连接的 DNS 结果做防重绑定校验，不能先验证一次再使用不受控的二次解析。明确 IPv4/IPv6 字面量与特殊地址范围，拒绝本地、私网、链路本地、环回、未指定和其他不适合作为公网目标的地址。对完整目标与重定向检查 301/302/303/307/308、非法 Location 和跳数上限。
- 每个 HLS 子请求都是独立安全边界，包括跨域引用与多跳重定向；限制协议、超时和资源，关闭客户端后回收上游。安全测试注入只替换解析结果或本地传输，不得替换被验证的公网地址判定逻辑；测试钩子必须显式启用且生产不启用。
- 同源访问/Host/Origin 防护维持原有边界。允许通过代理访问任意公网资源仍可能有滥用风险，资源预算和限流需要评审；本草案不声称代理自身能阻止全部外部攻击。

## 离线验收矩阵

所有网络仅使用本机 fixture、隔离临时应用根；录制浏览器和服务端实际请求，断言无外网连接。必须覆盖真实页面点击与真实 Player，而不只测试构造函数或 mock 回调。

1. **开关与动作**：默认关闭、仅 sidecar 开启、双方均开启、运行期关闭/迟到回调、file://、缺 HLS 库；明确试听与加入焦点和按钮动作。记录完整请求，试听及失败、重试、暂停、刷新、切台均无 `/api/mystation`/`/api/myradio` 写请求，`my-radio.txt` 不存在或逐字节不变；显式加入并探活成功后才有预期写入。
2. **身份**：新 URL、同名不同 URL、候选重复、命中首源和备选源、禁用源、隐藏台、多台共享 URL、加入后回绑、改名/分类、刷新及跨标签；确认收藏/最近不串台、不绕过现有策略，URL 原样进入统计与源记忆，临时身份不污染主列表。
3. **生命周期**：真实 Player 连接→播放→暂停→恢复→换台→失败/错误级联/重试/刷新，检查状态、统计及质量事件与正常播放一致，切台后旧回调不得复活或串台；所有网络请求始终代理，不产生第二播放器。
4. **HLS 全链**：实际 HLS fixture 包含多层 master/variant、相对及绝对 URL、跨域资源、分片、加密 key、字幕和备用音轨；统计浏览器请求，只允许同源受控代理，验证每层相对路径以重定向后的该层 URL 为基址。测试 Range 请求与响应、URL 中伪造 `/proxy?url=`、恶意协议、嵌套代理、畸形 URI、原生 HLS 环境以及不支持资源的 fail-closed；播放成功不能替代对子资源请求路径的断言。
5. **重定向与 DNS**：初始资源、每级清单、分片、key 等分别测试公网到公网、私网目标、无效 Location、301/302/303/307/308、跳数上限；DNS 首次公网而连接时变私网、每跳变私网、IPv4/IPv6 字面量及映射/CGNAT/变形地址。使用受控解析器但保留真实地址判定，检查实际私网 fixture 零命中。`VR_TEST_GUARD=1` 只能证明允许的本机媒体流程，不证明防护。
6. **回归与隔离**：现有台播放策略和默认开关字节不变；运行 `npm test` 及适用正式页面浏览器测试。仅离线可控媒体成功不证明真人试听、内容正确或国内直连可用。

## 待评审决策与放行条件

- 冻结临时候选身份、最近与收藏的持久化/回绑协议，决定 URL 歧义、隐藏和禁用的用户提示。
- 证明所选 HLS 方案涵盖当前打包版本支持的所有网络加载器及每层最终基址；无法证明则候选 HLS 必须关闭而非直连。
- 审查并测试现有代理/曲讯/台标等所有网络出口、特殊地址与重绑定；验证测试钩子不削弱生产判断。
- 独立安全复审、离线真实动作及回归全部通过后方可实现验收；生产发布仍须满足 C3 原有证据门。本文没有实现、没有执行上述验收，也不构成放行。
