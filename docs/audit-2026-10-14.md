## 二、安全发现（威胁模型：本机档 / 局域网档双定级）

### A1【P1·局域网档 / P2·本机档｜实测坐实】Windows 大小写绕过 data 段与 .bak 拦截

静态服务的隐私护栏 `server.js:276` 用**大小写敏感**的字面量比较：

```js
if (rel.split('/').some(seg => seg.startsWith('.') || seg.endsWith('.bak') || seg === 'data')) …
```

Windows 文件系统大小写不敏感，实测（win32 10.0.19045 + Node）：

- `GET /data/store.json` → 403 ✓；`GET /DATA/store.json` → **200，全量 store.json 内容返回**
  （收藏/健康标记/歌史/配置 = 全部个人数据，README 明言「HOST=0.0.0.0 局域网模式下不可被直接 GET」的承诺被击穿）
- `GET /radio.txt.bak` → 403 ✓；`GET /radio.txt.BAK` → **200**

本机档定 P2 而非 P1 的原因：跨源 JS 读不到（无 ACAO），需要配合 A3 的 rebinding 或直接网络可达才可利用。
修法（1 行核心）：`const s = seg.toLowerCase().replace(/[.\s]+$/, '')` 后再比较 `'data'` / `.bak`
（顺手吃掉 Win32 剥离尾部点/空格的变形，如 `data.`、`radio.txt.bak.`）。dotfile 的 `startsWith('.')`
不涉大小写，可不动。**注意 `/api/nowplaying` 的 `\.m3u8(\?|$)` 与 `player.js` 两处 m3u8 正则同为
大小写敏感**，属功能面非安全面，一并 lowercase 化更稳（`.M3U8` 现会走错分支）。

### A2【P2·实测坐实】/proxy 无跨源校验——任意网站可驱动本机代理

`/api/check`、`/api/sync`、`/api/store`、`/api/mystation`、`/api/nowplaying` 都有 `crossOrigin()`
前置，唯独流量最大的 `/proxy`（server.js:264）没有。实测：

```
curl -H 'Sec-Fetch-Site: cross-site' 'http://127.0.0.1:8199/proxy?url=http%3A%2F%2Fexample.com%2F' → 200（照常转发）
```

后果：任意网页可用 `<audio src="http://127.0.0.1:8137/proxy?url=…">`（媒体元素无需 CORS 即可加载）
把本机变成公开 http(s) 的流中继——带宽放大、以你的 IP 取内容。SSRF 内网面已被 `guardLookup` 堵死
（实测 IPv6 私网字面量 `fd00::1` → 502 ✓），所以危害上限是「公共目标中继」而非内网穿透。
修法：`/proxy` 入口加与 `/api/check` 同款的 `crossOrigin(req)` 检查。自用路径全部不受影响
（页面发起的 XHR/媒体请求 Sec-Fetch-Site=same-origin；地址栏直开 = none 放行；file:// 不走 proxy）。
注：Chrome 的 Private Network Access 已部分拦截公共页→localhost 的请求，Firefox/Safari 仍暴露，
按最弱浏览器定级。

### A3【P2·建议新增】Host 头校验——比逐端点补丁更根本的一揽子防 rebinding

现有 `crossOrigin()` 的盲区：**Origin 与 Host 比对在同源时永远相等**。DNS rebinding 攻击（攻击者域名
先解析公网 IP 加载页面，TTL 过后再解析 127.0.0.1）下，页面请求 `http://evil.com:8137/api/store` 时
Origin=Host=evil.com，Sec-Fetch-Site=same-origin——**所有跨源防线全部通过**，rebinding 页面可以：
GET /api/store 读全量个人数据、POST 覆写、触发 /api/sync、驱动 /proxy（叠加 A2 则无需 rebinding）。
修法（~4 行）：`HOST` 为回环模式时校验 `Host` 头只认 `localhost / 127.0.0.1 / [::1]`（任意端口），
不匹配返回 403；`HOST=0.0.0.0` 显式局域网档跳过校验（该模式本就是自担风险）。这是 Node 本地服务
防 rebinding 的标准做法，一处收口全部端点。

### A4【P3】静态路由不校验方法（旧审计新-6 复核：半修状态）

`POST /index.html` 实测返回 200。无副作用但语义松；`/api/store` 已有 405，静态侧补
「非 GET/HEAD → 405」两行对齐。

### A5【P3·纵深加固】safeTarget 不拒 IPv6 私网字面量

`safeTarget` 字符串层只拦了 `::1`/`[::1]`，`fd**/fc**/fe8~b**` 字面量靠 `guardLookup` 连接级兜底
（实测有效，502）。纵深建议：字符串层补 IPv6 字面量判断（照抄 `isPrivateIp` 的 v6 分支），fail-fast
省一次建连，也让「字符串级校验」这层名实相符。非漏洞，是纵深卫生。

### A6【P3】响应头缺 `X-Content-Type-Options: nosniff`

一行成本，堵 MIME 嗅探面（.txt 被嗅成 HTML 之类）。零依赖不破。

## 四、性能与体验

### C1【P2·本轮性价比最高】content-visibility：两行 CSS 吃下长列表布局/绘制大头

`render()` 整表 innerHTML 在 1521 台实测下字符串拼接与解析尚可，但**布局/绘制**随卡片数线性涨，
低端机滚动与重渲可感。零 JS 方案：

```css
#list .card { content-visibility: auto; contain-intrinsic-size: auto 132px; }
#list .row  { content-visibility: auto; contain-intrinsic-size: auto 44px; }
```

离屏卡片跳过布局/绘制/绘制缓存失效，渲染管线成本从 O(全部) 降为 O(视口)。与现有
`loading="lazy"` 台标、`swap` 淡入、reduced-motion 全部正交。intrinsic-size 给足近似高度避免
滚动条跳动（卡片 min-height:100px + padding 实测 ~132px，行 ~44px，以实测微调）。

### C2【P3】rememberVol 每次拖动事件全量序列化 volperst（旧审计新-4 复核：仍在）

音量条 oninput 直接触发 `JSON.stringify(volperst)`（上限 300 键 ≈ 15-20KB）+ localStorage 同步写，
拖动 = 每秒几十次。server 侧推流已被 Store 的 300ms debounce 攒批，**镜像侧没有**。修法：镜像写
尾随 debounce 300ms（崩溃丢最后 300ms 音量，无感损失），~5 行。

### C3【P3】http 模式每次刷新都加载 radio-data.js（~200KB）

它是 file:// 降级数据源，http 常规路径只在 `reloadMain()` 失败时才读 `window.RADIO_DATA`。
现有 1 天缓存缓解了重复下载，但「为罕见降级路径日常背上 200KB」可以改按需注入：reloadMain
失败分支里 `createElement('script')` 动态加载（时序上 fetch 失败回调里等 script onload 再
applySources）。收益中等，注意别破坏 file:// 静态 tag 路径与 AGENTS 的装载顺序契约描述。

### C4【P3】多标签联动不覆盖 view/theme/showdead 三个 UI 态键

`Store.apply()` 触发 `applyServerStore()` 重载 favs/cfg/health，但这三个键只更新了镜像，
按钮态/`<html data-theme>`/开关不跟随，刷新才生效。低频场景（两个标签页改主题），修法是在
`applyServerStore` 里补三键 UI 同步 ~10 行，或接受现状留档。

### C5【P3】stepFav 无收藏提示文案「点电台左侧 ☆」（旧审计新-2 复核：仍在）

网格视图收藏钮在卡片**右**侧。改「点电台旁 ☆」一劳永逸。

### C6【备忘·不建议】虚拟滚动

1521 台实测可接受；innerHTML 整表重建 + content-visibility 后余量更大。规模上万再议。
