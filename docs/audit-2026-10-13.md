## 二、新发现（按严重度）

> 本轮无 P1、无功能性大缺陷；1 项 P2（回归性质），其余皆 P3 长尾。编号「新-N」与历史 P 编号区分。

**新-1（P2·回归）`applySources` 背靠背双调 `rebind()`** —— app.js:131-132

```js
this.rebind(); // 收藏/最近按 URL 回绑（债务 1）
this.rebind(); this.render();
```

来源已定位：f74972a「chore: 收尾两个 nit —— 冗余 buildCats 双调清理」把原来的 `this.buildCats(); this.render();` 改成 `this.rebind(); this.render();`，而上一行本就有 `rebind()`——**清理重复的提交自己引入了重复**。后果：每次数据装配（boot / 同步 / 导入 / 添加电台）白付一倍 rebind（其内部 saveHealth + saveFavs + saveRecents 三次 localStorage 全量写 × 2，收藏/最近/死标的 O(n·m) 回绑扫描 × 2）。功能幂等，无正确性影响，浏览器点不出来——正是「零回归防护」会漏掉的那类问题（见 R1）。修法：删一行。

**新-2（P3·文案）`stepFav` 空列表提示误导** —— app.js:407-410

←/→ 切台从**当前可见列表**（受分类/搜索过滤）取收藏台；当前视图无收藏时报「还没有收藏电台——点电台左侧 ☆ 收藏后可用」。用户可能明明有收藏（只是不在当前分类），文案在撒谎。修法二选一：文案改「当前列表内没有收藏台（←/→ 在当前筛选范围内切台）」；或回退到全库收藏序（与锁屏 ⏮⏭ 同语义但范围更宽，需 owner 拍板口径）。

**新-3（P3·文档）README.md:5 行数失真**

「全部代码约 1600 行（前端按模块分四文件）」——r2 后全项目 2524 行（前端逻辑四文件 1572 + server/update-sources 635 + index.html 317）。「前端四文件 ~1600」仍成立，但「全部代码」口径已差 900 行。一轮三审刚修过同类勘误（F 组），r2 后又漂移。建议改为不写死数字，或拆成两个口径。

**新-4（P3·性能，已量化，可不修）`rememberVol` 逐事件全量落盘** —— player.js:85-91

音量滑杆 `oninput`（app.js:1034）每次事件都 `JSON.stringify(volperst)`（满载体 300 条 ≈ 12KB）+ `localStorage.setItem`。一次拖动 ~100 事件 = ~100 次同步全量写。实测 CPU 侧可忽略（200 次 stringify 共 5.9ms），桌面无感；低端设备理论上有抖动空间。改 `onchange`/pointerup 落盘或 300ms 防抖可归零——顺手项，非必须。

**新-5（P3·安全）`/proxy` 未挂 crossOrigin 护栏** —— server.js:202-208

`/api/check` 与 `/api/nowplaying` 都按「带副作用 GET」防了跨源驱动，`/proxy` 同样会开上游连接并持续拉流，却只靠「无 ACAO 不可读」挡**读取面**——跨源页面仍可借本机 8137 盲开任意公网连接（请求伪造 / 带宽放大，数据读不回来）。与本轮冒烟确认的 P2-9 同族但无回读面，故定 P3。闭合成本 3 行：hls.js 的 XHR 与 `<audio>` 同源请求带 `Sec-Fetch-Site: same-origin`、地址栏直开是 `none`，都过得了 `crossOrigin()` 检查；file:// 页面用不到 proxy（README 口径），不受影响。

**新-6（P3·硬化）静态路由不校验方法** —— server.js:210-223

POST/PUT 打静态路由照样回文件内容（HEAD 已由 Node `_hasBody` 机制自动处理，实测 200 无 body，非问题）。本机无实害；`if (req.method !== 'GET' && req.method !== 'HEAD') 405` 一行可挡。

**新-7（P3·数据）`cfg.tag` 只增不减的两条缝隙**

- `stMove` 选「↺ 默认分类」删 moves 但不清 tag（app.js:706-707，对照 cfgResetStation app.js:729 是清的）；
- `missList` 只扫 moves/names/hideS/srcs 四映射（app.js:738），tag 条目不进失配清单——上游 URL 漂移后对应的 tag 永远留在 cfg 里。

积累极慢、单条几十字节，但它叠加出**唯一没有 FIFO/总量封顶的 localStorage 键**（对照：logos 600 / health 500 / volperst 300 / srcmem 300 / songs 50 台 / mystation 500 行）。修法：tag 并入 missList 与 missclear 即可对齐既有风格。

**新-8（已知边界留档，非新发现）** 同步 diff 名单封顶 50（update-sources.js:372），消失收藏台 >50 时点名不全——AIbot P3-2 已记录在案，本轮复核确认仍在。维持现状可接受（全量点名状态栏也放不下），仅留档防重查。

## 三、架构评估

### 做得好的（应保持，不再动）

1. **模块契约执行严格**。本轮全文抽查：player.js 零处直接引用 App/Logos/DOM（状态外泄全经 onstate/onstatus/onfail/onlogo/onvol/onstepfav/onplaylast/ontick 八个回调）；logos.js 不碰播放；sync.js 只调 App/Player 暴露接口。一轮债务 2 的契约不只是写进了文档，是真的被执行了。
2. **身份公理已成本能**。r2 新增的五个持久层（volperst/srcmem/songs/health/cfg.srcs）无一例外按 URL 键 + FIFO 封顶，风格统一。这是三轮评审沉淀下来最值钱的资产：同步重建、上游改名、变体换序对它全部免疫。
3. **四层死链韧性成型**：同步实测（欧美系重建）→ 体检（含静默复查）→ 播放自愈（error 级联 + 看门狗 + 成功源记忆）→ 用户层手动追加源（探活先行、不动身份键）。每层职责清晰不重叠。
4. **防御性写盘全覆盖**：radio.txt / radio-data.js / logos.txt / my-radio.txt 四个产物文件全部 tmp+rename 原子替换，my-radio 再加串行写队列；同步侧上下限熔断（MIN_CN_ENTRIES/MIN_TOTAL）齐备。

### 下一次拆分窗口（建议随 B5 触发）

app.js 1081 行中维护面板域占约 330 行（面板自身 app.js:543-766 约 224 行 + boot 内接线约 107 行，另有 index.html 面板 CSS ~40 行），与主链路的耦合点只有 `state.stations`、`reapplyCfg`、`esc`——**接缝已经是干净的**，拆成 manage.js（经典 script、零构建，与既有五文件同模式）成本很低。roadmap 在列的 B5 电台详情面板预计 +200 行且同属「面板」域，建议届时一并做，避免 app.js 直逼 1300 行。

同时弹窗/浮层模式已第 4~5 次重复（manage 面板 / songhist / keys / sleepMenu / lowfreq 菜单各自手写 open/close/focus-return/Esc 互斥/点外关闭）：一个 ~30 行的 popover 小助手（开/关/焦点归还/互斥组注册）可以收拢，B5 做详情面板时顺手。

### server.js 归属错位（既有记录，到点评估）

server.js 从 update-sources.js require `checkStream/safeTarget/guardLookup`——「同步引擎」同时充当网络护栏提供方，是一轮债务 3 已记录的归属错位。现状 4 端点 + proxy + 静态尚可读；**触发条件不变**：下一个真正新增 API 端点的功能出现时，一并做「极简路由表 + net-guard/探测模块独立」。B5 的逐源体检可直接复用 /api/check（不加端点），第三上游是 CLI 侧改动——两者都不触发。

### 数据层演进备忘（远期，不动手）

- **localStorage 无版本键**：已有 13 个 `radio.*` 键，两次历史迁移（radio.last 并入 recents、radio.epg 清理）都是 boot 里零散处理。下次 schema 变更时建议引入 `radio.ver` + 迁移链，把散装 removeItem 收拢成一段。
