# Android 增量体检恢复：安全阻断草案

当前新增名单仅在内存，写入 radio 后进程退出会丢失；忙、取消、网络失败和健康写入失败也可能丢失。此草案不声称实现恢复：Android 设置页轻更新和端内同步的实际执行入口均默认阻断，明确提示，不改写 radio、任何 pending 或健康数据。已经在旧版本丢失的批次无法凭空还原。应用内其它调用者直接调用底层引擎不受此 UI 门保护；当前生产代码只有这两条调用路径。保留底层引擎与原有测试，以便后续完成协议后解除阻断。

解除阻断的必要条件：在共享 SyncBarrier 锁内，radio 改写前持久化版本化、完整且上限明确的 addedCheck 批次、目标内容 hash 和唯一代号；持久化失败或存在任何未识别/未完成批次时停止写入。恢复时只在目标 radio 的字节 hash 匹配、相关 full/light pending 已妥善协调时消费，不能用后续 diff 重建已丢批次。健康写入须有可靠的持久成功证明，成功后按代号比对清除；中断、网络、忙、取消及写入失败保留并安排重试。对旧 radio、目标 radio、未知状态、写盘与删除失败逐一注入故障，验证重启、幂等和并发，保证不覆盖旧任务。仅凭本草案的静态阻断测试不能证明这些协议已经实现。
