# 安卓新增台审查队列：边界

本阶段仅隔离实验，**未接生产写入或消费**，并未实现持久恢复。队列原型可保存完整批次、UUID、路径、旧/新全文 SHA-256 及每条候选原行，旧批次保留且集合有校验哈希；但无界增长、无界读取、不可访问文件的存在性歧义、无安全归档及确认机制，故不得接入同步。接线前必须解决这些问题，并证明队列故障在主库写入前中止且旧证据不受损。原子替换不保证掉电持久化或跨进程互斥。

原型沿用既有 diff，无法捕获同名台新增 URL，端内同步还会漏记跨分类同名新台，不能视为完整的 URL 候选集。轻更新既有新增判定为分类|名称，端内同步为全局名称；健康状态实际身份是源 URL，现有增量体检按名称匹配、截取 500 且不具备持久确认、冲突仲裁或按批重放。队列因此保留全部匹配原行及多源，不声称这些名称就是稳定身份。分类移动、同名跨分类、源变化不等价于真正新增身份；个人层、隐藏/禁用源及启动加载后的实际装配还需明确仲裁。欧美两节按既有策略排除。写前记录意味着失败或中断可留下未发布批次；新旧 hash 仅作证据，不代表发布成功。消费者未来必须核对实际库 hash、批次状态、URL 身份和用户数据，安全处理重复及部分进度，不能盲目重放。旧版已丢失的候选不可推断，现有范围警告仍保留。队列不接线消费，也不宣称恢复完成。
