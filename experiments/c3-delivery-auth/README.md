# C3 同 tree 投递认证：纯离线假体实验

基于 #86 的 c2cf839 提案；仅运行 `node experiments/c3-delivery-auth/test.js`。此目录不被生产代码、构建和测试入口引用，不允许接入生产；C3 仍为 No-Go。本实验不实现 v2 解析、pointer 决策、hash、网络、provider 认证、上游或许可验证。

可信配置显式授权仓库、40 位不可变修订和精确路径集合；调用者必须从独立受控策略获得这些值。本 fake 在同进程私有 WeakMap 签发不可伪造的对象句柄，句柄绑定 fake 实例、仓库、修订以及复制后的整个路径→字节快照。`open(evidence)` 验证后返回绑定该单一快照的 session，`session.read(path)` 不接受另一个证据；拒绝其他 provider、仓库、修订、路径、缺失文件和伪造对象，返回副本。配置及字节输入也复制，防止之后突变。fake 可为同一仓库和修订签发不同内容，因而各 session 绝不可互相混用；调用方负责整个选择过程只使用一个 session，API 无法阻止调用方自己混合两个 session 的结果。40 位格式本身不证明修订真实或不可变。

**信任边界**：测试者可以让 fake 签发任意内容，所以这只测试假体契约、不是外部证据，也不是对 GitHub 或其他 provider 的认证。任何未知 provider 没有签发能力，读取失败关闭；URL、TLS、服务自报、标签和哈希都不构成 tree 成员证明。`upstreamCommit` 与投递修订不同，不做等同或来源/许可断言。

## 本仓本地 Git 对象的可复用性评估

本仓是 Git 工作树，可用本地 commit、tree 和 blob 对象构建离线成员关系验证原型：可信配置先固定仓库身份及完整 commit，再逐层解析该 commit 的 tree，按路径查找普通 blob，读取原始字节并核验对象内容与对象 ID 的关系。不能使用工作区文件、分支名或多次独立 HEAD 读取代替同一 commit 的 tree；要明确拒绝或安全定义 symlink、gitlink、重复/歧义路径及对象缺失、损坏。Git 对象 ID/本地对象存在仅支持内容寻址和成员关系，不认证仓库身份、commit 真实性、签名、授权或许可；这些必须由独立可信策略和经过审查的认证证据提供。现有假体没有执行上述 Git 对象验证，也未实现真实适配器。

实际适配器需另行设计并独立安全审查：可信策略的供给和撤销、受认证 provider 证据的验证、修订到 tree 及每一路径和原始字节的密码学绑定、路径语义与重定向、资源上限及失败处理；还须考虑缓存、重放、身份变化和并发混树。没有经验证的真实证据时必须失败关闭，不因本实验通过而声称可上线。
