## 〇、范围声明（skill 适用性，诚实前置）

design-taste-frontend 面向 landing/portfolio 页，其第 13 节明确把「dense product UI」列在 sweet spot 之外。VRadio 是产品型播放器界面，因此本报告**只取用该 skill 中对产品 UI 成立的规则**：颜色校准（4.2）、形状一致性（4.4）、交互态完备（4.5）、内容密度（4.9）、性能与可访问性护栏（6.B/6.C）、暗色协议（第 8 节）、AI-tell 清单（第 9 节）、重设计审计协议（第 11 节）。hero/CTA/eyebrow/logo-wall 等 marketing 专属规则不适用，不予套用。

## 一、Design Read 与三拨盘

**Design Read**：个人自用的零依赖本地电台播放器，产品 UI，中文单用户，深色优先、浅色并列；视觉语言 = 「克制的工具型暗色 + 单一绿色强调」；技术底座 = 原生 CSS 变量双主题，零依赖硬约束。设计走**演进**：现有视觉基调是好资产，问题集中在信息降噪、对比度合规、交互态与图标语言，不在风格方向。

| 拨盘 | 现状读数 | 建议目标 | 说明 |
|---|---|---|---|
| DESIGN_VARIANCE | 2（均匀网格、完全对称） | 4（offset：留白与层级微调，不做艺术化） | 产品 UI，密度优先，对称是合理的，要加的是呼吸感与层级 |
| MOTION_INTENSITY | 2（hover 变色 + 脉冲/均衡器） | 3（状态转换反馈，全部 reduced-motion 降级） | 已有 reduced-motion 关怀（index.html:33），加动效必须延续该纪律 |
| VISUAL_DENSITY | 6.5（信息密、留白少） | 5.5（降冗余 + 放大网格单元） | 每卡固定 meta 行是「密而无信息」，砍冗余比加留白更重要；网格密度过高已由 owner 拍板下调（P2-8） |

## 二、总评

**这是一套 a11y 底子远超同规模项目、但「信息设计」欠收拾的界面。** 可访问性自觉（focus-visible / reduced-motion / aria-current / keepFocus / scroll-padding）和反馈闭环（连接脉冲、换源计数、空态行动指引）是真资产，全部保留。主要矛盾从「能不能用」转向「**看得清不清、找得快不快**」：浅色主题对比度不达标、卡片 meta 行零信息冗余、台标有无导致视觉节奏断裂、键盘导航在 1600 台规模下不可用、维护面板存在一个布局溢出实锤 bug。视觉风格本身不需要翻新。

| 维度 | 评分 | 一句话 |
|---|---|---|
| 可访问性 | 7/10 | 结构/键盘/语义底子好；浅色对比度三处硬伤 + 弹窗焦点管理缺失拉分 |
| 信息设计 | 5/10 | 卡片 meta 冗余、[国别] 噪音、列表视图浪费 3/4 宽度 |
| 交互效率 | 6/10 | 搜-播-藏闭环顺；方向键导航/随机换台/快捷跳转缺失 |
| 视觉设计感 | 6/10 | 基调克制统一；图标语言混乱、字阶扁平、卡片节奏参差 |
| 状态完备 | 7/10 | 空态/加载/错误叙事完整；无按压反馈、同步无进度感 |
| 布局正确性 | 6/10 | 桌面网格/移动端基本健康；面板「电台」页溢出实锤 |

## 三、实证发现

### P1 —— 正确性/合规硬伤（3 项，全部有截图或数值实锤）

**P1-1 维护面板「电台」页内容溢出弹窗，底部操作栏被顶出可视区**
截图 `05-manage-stations-overflow.png`：电台行浮出白色卡片底边、悬在遮罩上，`mfoot`（导出/导入/重置）完全不可见。
根因：`#mCats, #mlist { flex:1; overflow-y:auto }`（index.html:93）——`#mCats` 是 `.mbox`（flex 容器）的直接子元素所以成立；`#mlist` 挂在 `#mStations`（index.html:145，普通 div）里，`flex:1` 失效、`overflow-y:auto` 无高度约束永不生效，`#mStations` 以 `min-height:auto` 拒绝收缩，把 mbox 撑破。分类页内容少所以从未暴露。
修法 ~3 行：`#mStations { flex:1; min-height:0; display:flex; flex-direction:column; }`。

**P1-2 浅色主题三处对比度不达 WCAG AA（脚本实测）**

| 配对（浅色） | 实测 | AA 要求 | 受影响元素 |
|---|---|---|---|
| 强调绿 `--acc` 作文字 / 白面板 | **2.27:1** | 4.5:1 | 激活 chip、激活视图按钮、播放中台名、✓ 体检标、focus outline（3:1 也不达） |
| 警示橙 `--warn` / 白面板 | **2.95:1** | 4.5:1 | ✗ 体检标、file:// hint、维护面板失配清单 |
| 收藏金星 `#f5c542` / 白卡片 | **1.62:1** | （图形 3:1） | 已收藏台的金星在浅色下几乎隐形 |

深色主题全部通过（acc 7.23 / warn 5.56 / 金星 10.12），问题只在浅色侧。根源是 `:root[data-theme="light"]`（index.html:10）复用了为深色设计的 `--acc/--warn` 值，未按主题分档。
修法 ~4 行：浅色主题下重定义 `--acc: #1f7a54`（白面板 5.29:1 / 灰底 4.88:1，双面达标）与 `--warn: #b5431a`（5.55 / 5.12）、金星改 `#8a6508`（5.32 / 4.91，文字级达标）或 `#9a6d00`（4.60，图形级达标）；focus outline 自动跟随。
> ⚠️ 初版报告此处误荐 `#2e8b63 / #c05621 / #b8860b` 三个色值，二审脚本实测分别只有 4.21 / 4.57(灰底 4.22✗) / 3.25，至少在一个底面上不达 AA——已修正为上表实测通过值。详见七节 #2。

**P1-3 网格视图空态被压成 160px 窄条**
截图 `09-empty-grid-narrow.png`：`.empty`（index.html:83）作为 `.grid`（`repeat(auto-fill,minmax(160px,1fr))`，index.html:61）的 grid item 只占一格，文案逐 6 字折行挤在左上角。
修法 1 行：`#list.grid .empty { grid-column: 1 / -1; }`。

### P2 —— 信息设计与易用性（7 项）

**P2-1 卡片 meta 行在分类视图下 100% 冗余**
网格卡片固定渲染「分类 badge + N源」（app.js:279）。截图 `08-eu-grid-logos.png`：欧美音乐视图下 28 张卡全部是「欧美音乐 · 1源」——占卡片约 1/4~1/3 高度的一行零信息。华语音乐同理。该行在「全部/★收藏/最近」视图有区分度，分类视图下 100% 冗余（二审措辞修正：初版误写「只在全部视图有区分度」）。
建议：非「全部」视图下 meta 行降级（只保留源数且仅在 ≥2 源时显示）或干脆移除，卡片高度立省 ~20px。

**P2-2 欧美台名内嵌「[美国]」国别后缀是显示层噪音，且是截断主因之一**
**二审机制修正**：后缀不是上游带来的，是 `update-sources.js:209` 同步时本地追加的（`EU_COUNTRIES` 国名映射，update-sources.js:25）——实测 154 个欧美台中 **147 个（95%）** 带后缀，剥离后台名平均缩短 **26%**，全库最长台名 84 字。台名普遍因此超长触发两行截断：`SomaFM Groove Salad (128k MP…`、`101 SMOOTH JAZZ MELLOW…`（截图 08）；截断是「后缀 + 窄卡宽」叠加的结果，与 P2-8 放大单元互促。
建议：渲染前用正则把 `[xx]` 剥进 meta（或转 emoji 旗标），台名平均立短 26%。国别是同步引擎写入的有效数据，建议保留在 meta 层而非丢弃；不动 radio.txt，纯显示层。

**P2-3 台标有无导致卡片视觉节奏断裂**
logos.txt 只覆盖欧美系（二审实测：欧美音乐 67/154 ≈ **44%**、国际新闻·谈话 21/60 = 35%，其余分类 0），国内台全部纯文字（截图 01 vs 08）。有图卡与无图卡高度、密度、视觉重量不一致，列表视图尤甚（有图行 22px 头图 vs 无图行纯文字，行视觉重心漂移）。
建议：无台标时渲染**首字母色块**占位（确定性底色 = 台名 hash），统一节奏且强化可扫读性；零依赖可做，~15 行。

**P2-4 列表视图桌面宽屏浪费 3/4 视口**
截图 `02-desktop-dark-list.png`（1280px）：行内容贴左约 260px，右侧大面积空白，无 max-width 容器也无多列。
建议：`#list:not(.grid) { max-width: 900px; margin: 0 auto; }` 起步；或宽屏下列表自动双列。

**P2-5 键盘导航在 1600 台规模下不可用**
行/卡片 `tabindex=0`（app.js:277）+ Enter/Space 播放（app.js:552），但无 ↑↓ 方向键移动焦点、无 type-ahead——Tab 键要穿全库 1661 台（二审实测）个停靠点。`/` 聚焦搜索（已有）之后，自然期待 ↓ 直达结果第一条。
建议：roving tabindex + ↑↓/Home/End；搜索框 ↓ 把焦点交给列表首行。~30 行。

**P2-6 移动端 header 折三行占 ~150px**
截图 `06-mobile-390.png`：390px 下 header 折成（logo+搜索）/（视图+同步+体检）/（导入+导出+维护+主题）三行，加分类条共 ~150px 才见内容。同步/体检/导入/导出属低频操作，不应常驻首屏。
建议：≤640px 断点下低频按钮收进「⋯ 更多」菜单（原生 details/popover 即可），header 压回两行；footer 音量行保留。
二审补两条移动端观察：① 大量操作说明只存在于 `title` 提示（deadBtn/themeBtn/sleepBtn 等），触屏无 hover 等于不可达，「更多」菜单展开后需可见文案；② 收藏按钮命中区 ~24px 达 WCAG 2.5.8 下限但偏小，移动 pass 时一并放大。

**P2-7 维护面板弹窗无焦点管理**
`role=dialog aria-modal=true`（index.html:137）但打开时焦点不移入、Tab 可穿透到被遮罩的主页面、关闭后焦点不归还需要的位置。Esc 关闭已做（app.js:598）。
建议：打开时 focus 到关闭按钮、简单 focus-trap（Tab 循环 ~10 行）、关闭归还 `manageBtn`。

**P2-8 网格视图密度过高，单元面积太小（owner 反馈，2026-10-12 增补）**
`#list.grid { grid-template-columns:repeat(auto-fill,minmax(160px,1fr)); gap:8px }`（index.html:61）：1280px 宽下一屏 **7 列**（单元仅 ~171px）、1920px 下 **11 列**（~164px）。截图 `01-desktop-dark-grid.png` 可见卡片全部挤在一起：13px 台名两行截断、30px 台标、8px 内边距，卡片间只有 8px 呼吸缝，长台名卡片参差错落，扫读体验差。owner 拍板：放大网格单元、降低密度。
建议（一套组合，均可独立调参）：
1. 列宽一行改 `minmax(clamp(160px,18vw,230px),1fr)` + `gap:12px`——窄屏自动回到 160px 下限保手机 2 列（390px 下 18vw=70px 触底），桌面 1280px 得 **5 列**（单元 ~242px）、1920px 得 **7 列**，无需媒体查询；
2. 卡片内部随单元放大：padding `8px 10px → 12px`、min-height `76px → 100px`、台名 `13px → 14px`、台标 `30px → 40px`（~6 行）；
3. 与 P2-1（meta 行降级）、P2-3（首字母色块兜底）天然互促：大单元正好容纳 40px 色块，且 meta 精简后有留白可用。
验收时按截图对照微调 18vw/230px 两个参数即可，均为单行改动。

### P3 —— 设计感与精致度（8 项）

**P3-1 图标语言混乱（本报告最直观的「设计感」失分点）**
同屏混用两套图标语言（二审清点：**22 种字形，其中 7 种是彩色 emoji** 🙈👁🗑😴🌓☀️🌙，其余 15 种为单色字形 ▦☰⚙✕✎✓✗▶⏸●☆★＋↺⚠）：维护面板里 ✎（黑字形）挨着 🙈（彩色猴）尤其突兀（截图 04/05）。彩色 emoji 无法继承主题色，与克制基调冲突。
建议：统一为**内嵌单色 SVG sprite**（零依赖约束下不可用 npm 图标库；22 个字形可从 MIT 图标集如 Tabler/Phosphor 取 path 内嵌 + 注释署名，符合 skill「单一图标家族」纪律），或最低成本方案 = 全部改单色 Unicode 字形。详见开放决策 2。

**P3-2 字阶扁平、无字重层级**
二审清点：全站字号 **五档** 16/14/13/12/11px（初版漏计 11px），12px 一档被 14 处复用；字重层级只有浏览器对 `<b>` 的默认粗体（mhead/miss），正文层级全靠 1-2px 字号差 + 颜色硬撑。数字无 `tabular-nums`——睡眠倒计时每秒变宽引起 footer 每秒抖一次，是该项最直观的实例。
建议：字阶不必加档，补字重层级（台名 500/600、meta 400）+ `font-variant-numeric: tabular-nums` + sleepBtn 定 `min-width`，成本 ~5 行。

**P3-3 形状体系碎（二审清点 7 档，比初版判断更碎）**
二审 grep 实测圆角档位：**4px(badge) / 5px(行内logo) / 6px(fav、面板下拉) / 8px(btn、input、网格logo、miss) / 10px(card) / 12px(mbox) / pill(chip)** 共 7 档，另有 seg 拼接 0 与 eq 杆 1px 两处特例。初版报告误写「三档过细」，实况更碎。接近有规则但 4/5/6 三档差异完全不可感知。
建议：收敛为「容器 10px、交互件 8px、chip pill、badge 4px」明文规则，fav/下拉的 6px 归入 8px、行内 logo 5px 归入 4px 或 8px，改动量极小。

**P3-4 播放态双 ▶ 冗余 + live region 连刷**
播放中卡片名前有 ▶（index.html:30），footer `#now` 又是「▶ 台名」（app.js:326）；连接期 `#now` 与 `#status` 双 polite live region 同时刷新（docs/review.md 历史已提，仍在）。
建议：`#now` 去 ▶（footer 已有 ▶/⏸ 按钮 + 均衡器表达状态）；`#status` 降为 `role=status` 但连接期把文案并入 `#now` 单点播报。

**P3-5 分类 chip 无数量提示、无滚动渐隐**（历史评审已提，仍未落地）
1600 台规模下「综合·其他 519 台」与「常听 4 台」的点击预期完全不同。chip 条横向滚动在 Windows 下原生滚动条外露（截图 01/06 顶部）。
建议：chip 附 `10px` 数值角标（维护面板已有 cnt 数据，复用逻辑）；滚动容器加 mask 渐隐 + 细滚动条样式。~15 行。

**P3-6 footer 音量区素**（历史评审已提，仍未落地）
无静音键、无百分比、拖动无数值反馈。
建议：🔊/🔇 切换 + 拖动时 `#status` 或 tooltip 显示百分比。~15 行。

**P3-7 睡眠定时 discoverability 弱**
三态循环 15→30→60，唯一的说明在 title 里；倒计时Only 显示在按钮文本。想直接设 60 分钟要按三下。
建议：popover 列出 15/30/60/关 四选项一次点选（原生 popover 或 details），循环逻辑保留在 MediaSession 场景。~30 行。

**P3-8 同步缺进度感**（历史评审已提，部分落地）
ETA 文案已有（sync.js:48-50），但按钮只有文字变化，无不确定进度条。~10 行 CSS 动画（reduced-motion 静止）。

**P3-9 截断台名拿不到全名（二审新增）**
网格 `cname` 两行截断（-webkit-line-clamp:2）、列表 `.name` 单行 ellipsis，均无 `title` 属性——被截断的长名（实测最长 84 字）没有任何途径看到全文，hover/读屏都不行。与 P2-2/P2-8 同链条。
修法 1 行：行/卡片模板加 `title="${this.esc(s.n)}"`（走已有 esc 转义）。

### 要保留的资产（preserve list，重设计协议 11.C）

- a11y 骨架全套：focus-visible / reduced-motion / aria-current（互斥语义选型正确）/ keepFocus 重渲找回焦点 / scroll-padding 防 footer 遮焦点行
- 空态四分支行动指引文案；连接中脉冲 + 「源 i/N」换源叙事；失败给「体检/同步」下一步
- 克制基调 + 单强调色 + CSS 变量双主题架构（dark 侧全部达标，只修 light 侧）
- 网格/列表双视图 + 全部持久化（视图/主题/音量/收藏/最近/死台标）
- 反馈层次：连接中抑制 pause 图标闪烁（player.js:20）这类细节
- 紧凑代码风格与中文注释（本次所有提案按同等风格落地）
