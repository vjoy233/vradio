# Android addedCheck 持久待处理协议（设计草案，未接线）

基线：`5a7d643`。本文不是已实现的修复；不禁用全局同步，也不建议采用分离队列加盲重放。

## 问题与安全目标

轻更新和端内同步发布新 `radio.txt` 后才向 AppVm 返回 addedCheck，进程退出、协程取消、体检让位或 busy 时直接返回都会丢任务。下次 diff 已以新列表为旧侧，无法恢复。更早计算名单但在发布后落队列仍有同样窗口。Health.onDead 非幂等，简单重放可增加连续死亡次数，甚至误升停运档；健康写成功但队列确认前崩溃也不能盲重放。

目标：发布成功的每个已纳入 addedCheck 的项目至少保留到明确完成；写失败不得假确认；健康更新及完成见证原子提交；并发不覆盖导入或其他健康写。这里不承诺现有每批 500 截断之外的新增台，也不改变原有台名匹配语义。

## 建议协议（待实现和评审）

1. 发布前，先将带唯一批次 ID、原始名单和目标 radio 内容哈希的 prepare 记录原子持久化；必须合并此前未完成批次，不得以 500 截断历史积压。持久化失败则只拒绝本次发布，不全局禁用其他同步。端内同步需把 diff 计算移到写 radio 前。记录支持独立批次，不按台名全局去重，以免旧批次确认抹去新任务。
2. 发布必须串行；每次新发布前先持久解析前驱 prepare 的提交状态。仅已证明 committed 的批次可执行，不能按当前列表匹配推断发布成功。目标哈希不匹配时可能根本未发布，不能执行；无法证明状态则保留并停止该发布通道、明示恢复。旧/新哈希相同及 A→B→A 的 ABA 不能靠内容哈希判定：必须拒绝此类不明确提交，或引入可证明随发布原子推进且不会回退的世代见证；具体机制尚未实现。发布后的排队不得依赖调用方收到结果。
3. 体检先取主线程不可变的候选、身份和健康版本快照，再在 IO 探测。手动优先、网络失败、取消、被让位、未匹配、隐藏/全禁等均不确认对应任务；下次 Wi-Fi 启动及合适的空闲时机重试。必要时通过有界退避避免忙循环。
4. 使用 Store 单次原子写同时提交健康变更和私有完成见证（批次 ID + 项目 ID），而不是先写健康后删队列。该私有见证必须单独于 radio.* 白名单和导出数据，并且在 Store 初始化时加载、所有持久化路径保留；使用明确版本校验以及 copy-on-write，失败不改内存，版本冲突重新基于新快照决策，不能套旧结果覆盖健康写。考虑备份导入和回滚的版本检查，以及 rebind、健康清理、所有普通健康写与待检提交之间的串行化；探测期间身份/配置发生变化时保守丢弃结果，不确认任务。不能仅用 Store 的全局版本当作内存 Library 的完整并发证明。
5. 完成见证已落盘后才可异步整理 prepare 队列；即使整理失败或进程中断，重启时先读见证过滤已完成项，避免再次调用非幂等 onDead。队列整理和见证回收须有可证明的顺序及故障恢复，不能先删除见证；无法证明历史队列不可回退时不回收见证，容量满时拒绝新提交并明示，不能截断。导入不能抹去私有见证；回滚也不能无条件恢复旧见证。队列损坏/无法读取时 fail closed 并明示，不能当空队列覆盖。

## 需验证的关键边界

- 注入每个持久化步骤前后崩溃：prepare 前/后、radio 替换前/后、健康与见证事务前/后、队列整理前/后，重启核对无丢失且死亡次数最多增长一次。
- A→B→C 连续发布每步崩溃恢复、A→B→A 与旧新哈希相等、队列与 receipt GC 每步崩溃及旧快照回退；两次同步同名项目、不同批次，旧任务完成不得清掉新任务；同步发布失败留下的未发布 prepare 不得执行，也不得遗失旧任务。
- 手动体检抢占、boot 体检并发、取消、全网络失败、部分网络失败、库重载/配置变动、备份导入和回滚交错；写失败及版本冲突不确认。
- 文件损坏、存储满、队列积压、空名单、无匹配及隐藏/禁用台，均需定义可观察状态和有界资源策略。批次 ID 重复与见证清理顺序需要故障测试。
- 当前 `writeTextAtomic` 的 rename 原子性不等于断电持久化；若要求应对电源丢失，需另行验证文件和目录同步语义。上述主要针对进程崩溃/取消。

## 尚未解决

当前设计未定义跨多个版本列表完全失配时的终止/人工处理机制，也未完成 Store 私有见证与备份恢复事务的代码整合和并发证明。故本草案不能视为实现，也不应以盲重试代替上述工作。

未接线事务组件有两项**接线前阻断**：
- 导入旧健康快照时 receipt 仍保留，因此 ALREADY_APPLIED 只证明该操作曾经提交，绝不证明当前健康值仍包含其结果。需要设计导入世代、任务与见证的协调及回滚协议，定义导入后的恢复语义，完成交错测试前不得接线。
- 当前 Store 初始化区分不了瞬时读取失败与文件损坏；一旦读取失败会在后续普通持久化时写入永久 invalid 哨兵。私有事务随之 fail-closed，但重试、恢复、可观测性和数据修复机制均未设计；接线前必须解决，不能把瞬时故障当永久损坏。
