# C3 Web v2 独立解析实验

基于 #89 的共享合成 bytes 与 #86 的待评审 v2 提案；不接现有生产路径、不启用开关、不读取文件或联网。`c3-strict-v2.js` 接收已限长字节；调用者必须在读取流时提前执行上限，不能因本函数检查而无界缓冲。代身份校验的同步 SHA-256 由调用者注入，测试用 Node crypto；仅哈希一致不证明来源、许可或连接安全。

`test/c3-web-strict-v2.js` 直接解码共享 base64，核实真实字节摘要/长度并断言 sidecar、pointer、manifest 及选择结果；本地回退和 commit 绑定仅为测试模拟，不是 Web 运行时流程。独立实验未在浏览器或 Android 真机验证，也不等于生产接线或发布许可。

## 待评审缺口

- 受控来源、不可变 commit 的取得、引用完整性及绑定 API 尚未定义。fixture 的 `binding` 只是测试注入，不能证明可信绑定；previous 选择测试仅按示例比较绑定值，不代表实际安全机制。
- previous 回退降级状态、错误优先级、缓存撤销策略未定义；本测试不推断。pointer 无效后的 Android 本地回退仅以测试模拟表达，不实现真实缓存或撤销。
- URL 端口前导零、日期年份 0000、百分号编码语义等应由双端评审明确。提案的「整数」是否排除 `2.0` / `2e0` 及 RFC 3986 方括号是否允许出现在 path/query 应明确：本实验与 Android 暂建议采用仅整数字面量且拒绝 path/query 原样方括号的保守规则，未冻结。
- 实验性安全约束：JSON 容器最大深度为 3（根对象 → items 数组 → item 对象），递归前检查；合法 schema 不需要更深。旧实现深嵌套可在 schema 校验前栈溢出，Android 需保持一致。格式/schema 合规不证明连接安全，也不是 SSRF 防护。
- 提案限制读取时立即中止，纯函数只能校验已提供的字节长度；未来 I/O 层必须独立验收。
